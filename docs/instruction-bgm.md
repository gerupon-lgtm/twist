# twist 次の版の指示：BGM（SCC＋PSGで鳴らすオリジナル曲）

「振動と効果音」の版が終わってから取りかかってください。音源の組み込み（SCCシミュレーターのファイル、PSG 2台の構成）は、その版で済んでいる前提です。

## 背景（なぜ入れるか）

- 発案者の希望は、SCCとPSGで鳴るBGMを付けることです。
- 曲は、まず**Codexが仮のオリジナル曲を作ります**。後で発案者が自作のMIDIファイル（SMF）に差し替える可能性があります。
- そのため、**曲のデータを差し替えやすい作り**にすることが一番大事です。

## 前提（確認済み）

- SCCシミュレーターには、MIDIファイルを再生する部分 `src/engine/smf-player.js` があります（版0.8.12、コミット `0036288a134a79b1855915eac47ff09634295e7f`）。
  - MIDIチャンネル1〜8：SCCのパート1〜8
  - MIDIチャンネル10：PSGの擬似ドラム（`src/engine/psg-drums.js`。GMの打楽器の配置）
  - 9・11〜16チャンネルは鳴らしません。
  - 詳しい決めごとは、SCCリポジトリの `docs/api-design.md` にあります。
- SCCの波形（音色）の初期の組は、`src/core/presets.js` にあります。
- MGS形式の曲も再生できますが、MGSDRV本体はリポジトリに含まれていません。twistに同梱してよいかどうか（配布の条件）も未確認なので、今回はMIDIファイルを使います。

## やること

### 1. 曲のデータの形

- 曲は**標準MIDIファイル（.mid）**として置き、上の再生部分で鳴らします。
- 発案者がDAWで作ったMIDIファイルを、ファイルを差し替えるだけで使えるようにします。
  - 曲ファイルの置き場所と、パートごとの音色（SCCの波形の番号）・音量の対応を、1つの設定ファイル（例：`public/music/tracks.json`）にまとめます。
  - ループの開始位置と終了位置を、設定ファイルで指定できるようにします（MIDIファイルの中の印でも構いません）。
- 差し替えの手順を `docs/music.md` に、発案者が読んで分かるように書いてください（DAWでの書き出し設定、使えるチャンネル、同時に鳴らせる音の数、ドラムの配置）。

### 2. Codexが作る仮の曲

- **オリジナル曲**を作ります。既存のゲーム音楽やほかの曲を写したり、似せたりしないでください。
- 曲の雰囲気：空を飛ぶ爽快感のあるもの。1980年代のMSXのゲーム音楽のような、SCCらしい音色を活かします。
- 長さは、ループで30〜60秒程度。テンポや調はお任せします。
- 使う音：SCC 5チャンネルまで（メロディ・伴奏・ベースなど）と、PSGのドラム。BGM用PSGの3チャンネルはドラムで使い回されます。
- 曲は、プログラムで生成する方法でも、手で書いたデータから作る方法でも構いません。作り方と、作るための元のデータ・スクリプトもリポジトリに残してください。
- ゴール時のファンファーレも、短いオリジナルのジングルとしてBGM用の音源で作り、効果音用PSGの代用から差し替えます。

### 3. 鳴らし方

- 開始ボタンを押した後、飛行が始まったらBGMを流します。
- 一時停止では小さくするか止め、再開で戻します。どちらにするかは、Codexが判断して記録してください。
- 墜落・ゴールでは、BGMを止めて、それぞれの音を目立たせます。
- 効果音は、別の効果音用PSGで鳴るので、BGMを途切れさせません。

### 4. 設定と記録

- 調整パネルに、BGMのオン・オフと、BGMの音量（効果音と別に）を追加します。
- 記録とコピーに、BGMの設定と、鳴らした曲の名前を含めます。

### 5. 版番号・記録

- 版番号を上げ、README と `docs/verification-v01xx.md` を更新します。
- 処理の重さ（BGM＋効果音＋3D描画）を検証表示に出し、Pixel 9aでの確認は発案者に依頼する形で記録します。

## 変えないもの

- 操縦の入力、物理計算、表示、振動、効果音の内容。
- SCCシミュレーターのチップの計算と、MIDI再生部分の決めごと（チャンネルの割り当てなど）。

## テスト

- 単体テスト：
  - 設定ファイルの読み込み。ファイルが無い・壊れているときは、BGMなしで遊べること。
  - ループの位置で、正しく先頭（ループ開始位置）に戻ること。
  - BGM用への書き込みが、効果音用PSGに影響しないこと。
- ブラウザーテスト：
  - 開始ボタンを押す前に、音が出ないこと。
  - BGMのオン・オフ、音量の保存。
  - 一時停止・墜落・ゴールでの止め方が、決めたとおりであること。
  - 別のMIDIファイルに差し替えても動くこと（テスト用の短い曲で確認）。
- 既存のテストはすべて通ること。
- 曲の聞こえ方と処理の重さは、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 曲の内容、テンポ、音色、音量、ループの長さ、一時停止時の扱い。
- 設定ファイルの形と置き場所。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 既存の曲を写すこと、似せること。
- MGSDRV本体を同梱すること（配布の条件を確認するまで）。
- SCCシミュレーターのチップの計算を変えること。ライセンス表示（NOTICE）を外すこと。
- 開始ボタンを押す前に音を出すこと。
- 端末の外へ情報を送る処理の追加。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
