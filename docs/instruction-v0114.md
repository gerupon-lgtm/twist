# twist v0.1.14 指示：自機を固定して景色が回る表示モードを追加する

## 前提の確定（v0.1.13の実機結果）

- 機首の上下は `pitch=angle`（傾き＝角度）を**標準**にします。`pitch=rate` は比較用の選択肢として**残します**。
- 実機で試した記録（1人分）は次のとおりです。
  - angle：約240秒で墜落1回、クリア。飛び直した後は、復帰補助0秒・墜落0回でした。
  - rate：約111秒で墜落3回、クリアなし。
- 操作した本人の感触でも、angleのほうが良好でした。

## 背景（なぜこの表示を追加するか）

発案者が最初に目指していた見え方は、次のとおりです。

> スマホを回しても、自機は人から見て常に同じ向き（上向き）を保ち、周りの景色が回る。

v0.1.0〜v0.1.10では、スマホの回転を**3方向すべて**打ち消すように、**自機の模型**を回していました。その結果、次の問題が起きました。

- 前後・左右の傾きは操縦の入力そのものです。これまで打ち消したため、自機が真横から見えて細くなりました。機首の向きも判定できなくなりました（`projectedTiltAngles` が無効を返す）。
- 翼の傾き（バンク）と補正がぶつかり、右旋回で機首が左を向く不具合が出ました（v0.1.11の記録）。

そこで今回は、次の考え方で作り直します。

1. 打ち消すのは、**画面の面内で回す動き（1方向）だけ**です。前後・左右の傾きは、入力と画面の見やすさのために打ち消しません。
2. 回すのは自機の模型ではなく、**カメラ（画面全体の見え方）**です。カメラを視線の軸で回せば、毎回3Dで描き直すので、画面の角に空白が出ません。
3. 翼の傾きは、自機を傾けて見せるのではなく、**景色（地平線）を傾けて**見せます。

## やること

### 1. 表示モードの切替を追加する

- URLパラメータ `display=bank|fixed` を追加します。
  - `bank`（現行・標準）：v0.1.13の表示をそのまま残します。
  - `fixed`（新規）：自機を固定し、景色が回る表示です。
- 開始画面と一時停止画面に、旋回や機首方式と同じ形の切替を置きます。切り替えたときの扱いは、既存の「見え方（見失い対策／従来）」と同じにします（位置と向きを保ったまま、表示だけを切り替える）。
- `display` は表示だけを変えます。操縦の入力、飛行の計算、当たり判定には影響させません。

### 2. `fixed` の見え方

- **自機**
  - 画面中央に置きます。
  - 翼の傾きでは自機を傾けません。
  - スマホを面内で回した分だけ、画面上で逆に回します。これで自機は、人から見て常に上を向いたままになります。
- **景色**
  - 翼の傾きの分だけ、地平線を傾けます。
  - スマホを面内で回した分も、自機と同じだけ逆に回ります。
  - 結果として、プレイヤーから見た地平線の傾きは「翼の傾き」だけになります。
- **文字・メーター・ボタン（HUD）**
  - 回しません。今までどおり、画面の縦横に沿って表示します。
- **面内で回す角度の取り方**
  - 中立の持ち方からの面内回転を使います（`relativeAngles` / `deviceTiltAngles` の `twist`。半回転付近で折り返す `foldedTwist` は操縦用なので、表示には折り返す前の角度を使ってください）。
- **実装のヒント**
  - スマホの面内回転は、カメラを視線の軸で回すことで表現します。
  - 翼の傾きは、今の `syncWorld` が `world` に入れている回転を使います。
  - 自機は `craft.quaternion` を、翼の傾きに関係なく一定にします。
  - より良い方法があれば、理由を記録して採用して構いません。

### 3. 確認してほしい関連箇所

- **画面端の目標マーク**（`visibility.js`）：カメラを回したときも、矢印が正しく目標の方向を指すこと。
- **地面を見る表示補助**（`flight-view.js`）：今は表示上の翼の傾きを±15度に抑えています。`fixed` で地平線が翼の傾きを正しく示すよう、必要なら調整してください。`bank` 側の挙動は変えないでください。
- **「回す」旋回との組み合わせ**：面内で回す動きが、操縦の入力と表示の補正の両方に使われます。ハンドルを回しても景色が現実の向きに留まる見え方になるはずです。両方の旋回方式で確認してください。
- **画面の自動回転**：スマホを大きく回すと、ブラウザーが画面の縦横を切り替えることがあります。そうなっても、自機が人から見て上向きを保つことが目標です。難しければ、`fixed` のときに「画面の回転ロックをおすすめ」と案内する方法でも構いません。どちらにしたか、理由を記録してください。

### 4. 手ぶれへの対策

- センサーの細かな揺れがそのまま画面に出ると、見づらくなる可能性があります。表示の回転だけに、軽いならし（追従の時定数）を入れてください。初期値は0.05秒程度とし、調整パネルで0〜0.3秒の範囲で変えられるようにします。
- ならしは表示だけに使い、操縦の入力には入れません。

### 5. 記録の改善

- 「設定をコピー」と結果のコピーに、次の項目を追加します。
  - 結果：`"result":"clear"`（クリア）／`"grounded"`（墜落）／なし（途中）
  - 表示モード：`"display":"bank"` または `"fixed"`
  - `pitch=rate` のときは、使わない設定（`maxPitch`、`timeConstant`）を出さないか、使っていないことが分かる形にしてください。
- 結果画面にも「クリア」「墜落」を表示します。

### 6. 版番号・記録

- 版番号をv0.1.14へ上げます。README、公開URL、`docs/verification-v0114.md` も更新します。
- READMEの公開URLには、`pitch=angle` を標準として、`display=bank` と `display=fixed` の両方を載せます。`pitch=rate` の比較用URLも残します。

## 変えないもの

- 物理計算と、失速からの復帰補助です。
- 操縦の入力の計算（angle／rate、ひねる／回す）です。
- 探索モードです。
- `display=bank` の見え方です（今までどおり動くこと）。

## テスト

- 単体テスト：
  - `fixed` で、カメラの面内回転がスマホの面内回転に一致すること。
  - 自機の向きが、翼の傾きによって変わらないこと。
  - 景色の傾きに翼の傾きが入っていること。
  - 無効な値でも、有限で安全な結果になること。
- ブラウザーテスト：
  - 疑似センサーで面内を30度回したとき、`fixed` では自機の上向きが現実の上向きを保つこと（画面上では逆に30度回る）。
  - HUDが回らないこと。
  - 画面端の目標マークが正しい方向を指すこと。
  - `bank` が従来と同じ結果になること。
  - 記録に `result` と `display` が入ること。
- 既存のテストはすべて通ること。
- スマホ実機での見え方、酔いやすさ、手ぶれの感じ方は「未確認」として記録に残してください。PCでの疑似操作の成功を、実機確認の代わりにしないでください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 初期値（ならしの時定数など）、スライダーの範囲、切替の配置、文言、色。
- 実装方法（上のヒントより良い方法があれば、理由を記録して採用してください）。
- どちらの表示を標準にするか。
- 画面の自動回転への対応方法。

**変えないもの（指示があっても確認してから）**
- 端末の外へ情報を送る処理は追加しません（設定と記録は端末内だけで扱う）。
- センサーの許可の取り方と、停止・再開時に速度と出力を0へ戻す安全側の動作は維持します。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
