# twist 次の版の指示：ステージ開始前の「上から見た簡単な地図」（ブリーフィング）

作業中の版があれば、その次の版として出してください。高速空域（試作）より前に入る場合は、高速空域ができたときにも同じ仕組みで表示されるように作ってください。

## 背景（なぜ入れるか）

- 発案者の希望：「ステージ開始時に、上から見た雑な地図を表示して、目標の大まかな位置を確認できる導入部分があるとよさそう。スキップできるようにして」。
- これまで、目標を探すことに気を取られて操作が分からなくなる、という課題がありました。案内（フライトディレクターなど）で飛行中の負担は減りましたが、**飛ぶ前にコース全体の形を頭に入れておく**と、次の目標の方向を予想しやすくなります（実機のパイロットが飛ぶ前に行う「ブリーフィング」と同じ考え方）。
- 3コースや高速空域でコースが長くなり、目標の数も増えたので、全体像をつかむ価値が上がっています。

## やること

### 1. 上から見た地図（ブリーフィング画面）

- コースを選んで開始する直前に、コース全体を真上から見た簡単な地図を表示します。
- **表示するもの**
  - 開始位置と、開始時に向いている方向（矢印）。
  - 目標（TGT 1〜n）の位置と番号、それぞれの高さ（例：`TGT 3 ▲28m`）。
  - EXITの位置。
  - 目標を順に結ぶ線（おおまかな飛ぶ道筋）。
  - ABの直線区間（ある場合）。
  - ステージの端、中央の塔などの目印。
  - 方角（北の印）と、距離の目安（例：`100m`、高速空域なら `1km` の目盛り）。
- **地図の向き**：開始時に向いている方向を上にします（レーダーと同じく「進む方向が上」）。北の印も付けます。
- **見せ方**：開始位置から目標を順に結ぶ線を、数秒（目安：3〜5秒）かけて描いていくと、順番が頭に入りやすくなります。描き終わったら、そのまま止まって表示を続けます。
- 雑な地図で構いません。線と記号だけの、簡単な見た目にします（HUDと同じ英語表記）。

### 2. スキップと表示のしかた

- **スキップ**：画面のどこかをタップするか、「SKIP」ボタンで、すぐに飛行の開始へ進めます。
- **表示の設定**（調整パネル）：「毎回表示する」「コースごとに初回だけ表示する」「表示しない」から選べるようにします。初期値は「毎回表示する」。
- **タイム**：コースの時間（タイム・自己ベスト・区間時間）は、地図を閉じて飛行が始まってから数えます。地図を見ている時間は含めません。

### 3. 飛行中に見返せるようにする

- 一時停止画面から、同じ地図を開けるようにします（「MAP」ボタン）。
- 飛行中に開いたときは、今の自機の位置と向き、取り終えた目標（薄く表示）も重ねて表示します。

### 4. 開始の流れとの関係

- 今の開始の流れ（センサーの許可、持ち方の合わせ直し、開始ボタン）を壊さないようにします。地図をどこに挟むのが自然かは、Codexが判断して記録してください（例：コースを選んだ直後、または持ち方を合わせる前）。
- 開始ボタンを押す前に、音や振動は出しません（今までどおり）。地図を描く演出に音を付ける場合は、開始ボタンを押した後だけにします。

### 5. 記録

- 記録とコピーに、地図を表示したか・スキップしたか・見ていた時間を追加します。地図を見たかどうかで、区間時間が変わるかを比べられるようにするためです。

### 6. 版番号・記録

- 版番号を上げ、README、`docs/settings-guide.md`（表示の設定）、`docs/verification-v01xx.md` を更新します。

## 変えないもの

- コースの配置、飛行の計算、取れる判定。
- 案内、HUD、レーダー、音、振動の内容。

## テスト

- 単体テスト：
  - 地図の座標変換（コースの座標 → 画面上の位置。開始方向を上にする回転、縮尺）。3コースと高速空域（ある場合）の両方で、全目標が画面に収まること。
  - 表示の設定（毎回・初回だけ・表示しない）と、初回の判定の保存。
  - タイムが、地図を閉じてから数え始めること。
- ブラウザーテスト：
  - コースを選ぶと地図が出て、タップまたはSKIPで開始へ進めること。
  - 一時停止画面からMAPを開くと、自機の位置と取り終えた目標が表示されること。
  - 開始ボタンを押す前に、音や振動が出ないこと。
  - 390×844・360×640・844×390で、地図の全体と文字が画面に収まること。
- 既存のテストはすべて通ること。
- 実機での分かりやすさは、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 地図の見た目、表示する項目、描く演出の長さ、地図を挟む位置、表示の設定の初期値。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 地図を見ている時間をタイムに含めること。
- 端末の外へ情報を送る処理の追加（設定と記録は端末内だけで扱う）。
- 開始ボタンを押す前に音や振動を出すこと。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。発案者が不在の場合は、安全側で仮決めして `docs/open-questions.md` に記録し、先へ進んでください。
