v0.1.30は現在開発中で、未公開・最終統合検証前です。v29の確認済み配信ファイルを保存版29としてローカルへ準備しましたが、その版別URLの初公開確認はv30の公開後に行います。保存と配信成功を混同しません。

## 比較するときの前提

- `course=legacy`は、開いている版の飛行計算で旧配置を使う指定です。v0.1.25の旋回をそのまま比較する場合は、公開確認済みの保存版を開きます。
- URLの`v=0.1.25`だけで、最新版のURLが過去版の配信へ切り替わる仕組みではありません。版を固定する比較には`/versions/0.1.25/`のような専用パスを使います。
- 版別URLは同じサイト内なので、同じブラウザーの設定保存を共用します。以前の版で保存すると、後から追加された設定項目が既定値へ戻る場合があります。比較前後に、その版の設定と記録を一緒にコピーしてください。
- ホーム画面のアプリは最新版用です。保存版の比較はブラウザーで行います。端末へのインストールや実機の動作を、保存ファイルの検証だけで確認済みとはしません。

## 保存と公開の確認手順

1. その版の全テスト、ビルド、公開ファイルと公開画面の確認を完了し、コミットとPages実行を記録する。
2. `dist`直下の配信ファイルを`public/versions/<版>/`へそのままコピーする。すでに含まれている`versions/`は除外し、版を再帰的に入れ子にしない。ライセンス、音楽、アイコン、workerも含める。
3. 元の公開確認のファイル数・長さ・SHA-256と、保存ファイルを比較する。Windowsの改行変換やビルド時の書式処理で、保存版のHTMLを書き換えない。
4. 次の版の配信に含め、保存版の全ファイルのHTTP状態、MIME（配信ファイルの種類）、長さ、SHA-256（バイトの一致を確かめる値）を確認する。v0.1.25の`version.json`と画面は0.1.25のままであることを確認する。
5. 保存版のHTMLが指す配信用スクリプト（module）を読み込むこと、`/src/`への絶対参照がないこと、保存版のパスを範囲とするサービスワーカー（通信を扱うブラウザーの処理）が制御すること、CacheStorage（保存用キャッシュ）が空であることを確認する。
6. 実際の開始操作後の英語HUD、日本語の停止画面、再読込後の版とworker、実行／HTTPエラーを確認する。成功後に上の表と比較リンクを確定する。

v0.1.26の公開では、最新版21ファイルと保存版v0.1.25の21ファイル、計42ファイルの公開一致と、保存版のブラウザー確認が成功しました（2026-11-08）。

準備した確認用スクリプトは`.cache/v0126-public-verify.mjs`と`.cache/verify-release-archives.mjs`です。前者は現在版と保存版の配信全体、後者は`public/versions/`の各版の実画面と専用workerを確認します。旧版の成功記録を上書きしない名前で出力します。実行結果は`.cache/v0126-public-verification.json`と`archives-v0126-verification.json`に保存しました。
