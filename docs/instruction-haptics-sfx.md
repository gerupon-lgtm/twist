# twist 次の版の指示：振動と効果音（SCCシミュレーターの音源を組み込む）

作業中の版があれば、その次の版として出してください。BGMは、この次の版で別に扱います（別紙）。

## 背景（なぜ入れるか）

- 傾き操作のゲームでは、プレイヤーが画面をじっと見続けにくいです。失速の手前や地面への接近を、**振動と音でも**知らせると、見落としが減ります。
- 発案者の希望は次のとおりです。
  - Pixelで振動させたい。光を取ったときやゴールのときにも振動させたい。
  - 音を付けたい。音源は、発案者が作った**SCCシミュレーター**のSCCとPSGを使いたい。
  - 揺れ方は、発案者のイメージより**実機の飛行機の動きに合わせることを優先**する。

## 前提（調べて確認したこと）

### 振動（Vibration API）
- `navigator.vibrate` は、「何ミリ秒振動して、何ミリ秒止める」のオン・オフしか指定できません。強さは変えられないので、**一定時間の中で振動している割合**で強弱を表します。
- 対応しているのはAndroidのChromeです。iPhoneのSafariは対応していません。振動はPixel（発案者の実機：Pixel 9a）専用で構いません。
- 画面を一度タップした後でないと振動できません（開始ボタンで満たせます）。

### 実機の飛行機の揺れ方
- 普段の飛行では、機体はほぼ揺れません。エンジンの細かな震えがある程度です。
- 揺れの原因は、速度そのものではなく、**迎え角（翼に当たる風の角度）が大きいこと**です。失速の手前から機体が震え始めます（バフェット）。失速すると、大きく不規則に揺れます。
- 迎え角は、すでに `flight-physics.js` が `angleOfAttack` として計算しています（失速の始まり20度、完全な失速70度）。

### 音源（SCCシミュレーター）
- リポジトリ：`https://github.com/gerupon-lgtm/SCC`（公開先 `https://scc-sim.sikumilab.com/`）。今回の基準は **版0.8.12、コミット `0036288a134a79b1855915eac47ff09634295e7f`** です。
- 音は AudioWorklet（音を作る専用の処理）の中で作られます。画面やMIDIとは切り離されています。
  - SCC：`src/core/scc-fast.js`（高速版。基準版 `scc-ref.js` と完全一致をテスト済み）、`scc-registers.js`、`scc-ext-registers.js`
  - PSG：`src/core/psg-ref.js`（AY-3-8910。音程3チャンネル、ノイズ、エンベロープ）、`psg-stage.js`
  - 変換・後処理：`window-converter.js`、`post-stage.js`
  - Worklet：`src/audio/scc-worklet.js`、メイン側：`src/audio/audio-engine.js`
- Pixel 6aでの処理の重さは、5音を同時に鳴らして最大10%でした（SCC側の記録）。Pixel 9aで、3D描画と同時に動かしたときの重さは未測定です。
- ライセンス：MAME由来の部分（BSD-3-Clause）があります。表示はSCCリポジトリの `NOTICE` にあります。SCCシミュレーター本体のライセンスは未定ですが、発案者本人の作品なので、twistで使うことは発案者が了承しています。

## やること

### 1. 音源の組み込み

- SCCリポジトリの上記コミットから、必要なファイルを**twistに写して入れます**。実行時にSCCのサイトから読み込む方式は使いません（SCC側を更新するとtwistの音が変わるため）。
- 写したファイルの取得元とコミットを記録し、`NOTICE` を写してtwistの画面（またはREADME）からライセンス表示を見られるようにします。
- MGS（MGSDRV）の再生部分は、今回は不要です。Worklet が `mgsdrv-host.js` を読み込んでいるので、twist用の Worklet を用意して外すなど、必要な部分だけ使う形にして構いません。
- **実装のヒント**：AudioWorklet の中のファイルは、Vite がまとめて扱えない場合があります。`public/` に置いて相対パスのまま読み込む方法などが考えられます。より良い方法があれば、理由を記録して採用してください。
- 写したファイルの中身（チップの計算）は、変えないでください。twist側の都合で変える必要が出た場合は、変える前に理由を書いて質問してください。

### 2. PSGを2台にする

- **BGM用**：SCC＋PSG1台（BGMは次の版で入れる。今回は鳴らさなくてよいが、場所を空けておく）。
- **効果音用**：PSGをもう1台用意して、効果音はこちらだけで鳴らします。
- 実機のMSXにはPSGが1台しかないので、実機どおりではありません。BGMのドラムが途切れたり、ノイズの高さが効果音と取り合いになったりするのを避けるための、発案者の判断です。
- 2台の音量の釣り合いは、SCCシミュレーターの `PSG_GAIN` と同じ考え方にそろえます。全体の音量は、聴覚への配慮で控えめの初期値にします。

### 3. 効果音

効果音用PSG（音程3チャンネル＋ノイズ）で鳴らします。

| 場面 | 音の案 | 実機との関係 |
|---|---|---|
| エンジン | 出力に応じて高さが変わる低い音。ノイズを少し混ぜる | 実機もエンジン音は出力で変わる |
| 風切り音 | 速度に応じて大きくなるノイズ | 実機も速いほど大きい |
| 失速の手前 | ガタガタした低いノイズ。振動と同じリズム | バフェット |
| 失速の警告 | 断続的なブザー | 実機にも失速警報の音がある |
| 地面に近い（既存の赤の警告） | 短い警告音の繰り返し。振動と同じリズム | 実機の対地接近警報に相当 |
| 光を取った | 上がっていく短い音 | ― |
| ゴール | 短いファンファーレ（BGMが入るまでは効果音用PSGで代用してよい） | ― |
| 墜落 | ノイズの爆発音が、だんだん消える | ― |

- 3チャンネルの割り当て（たとえば、エンジン・風切り音を常に1チャンネル、警告で1チャンネル、出来事で1チャンネル）と優先順位は、Codexが決めて記録してください。出来事の音（光・ゴール・墜落）が、常に鳴っている音に負けないようにします。
- 音色は耳で調整する前提の仮の値で構いません。値を1か所にまとめて、後で調整しやすくしてください。

### 4. 振動

- **常に続く振動**（迎え角などで強さを変える。一定の周期の中で振動する割合で表す）
  - 通常飛行：エンジン出力に応じた、ごく弱い震え。調整パネルでオフにできる。
  - 失速の手前：迎え角14度前後から弱く震え始め、20度に近づくほど強くする。
  - 失速中：大きく、不規則に揺れる。
  - 迎え角の値と強さの対応は、仮の値で構いません。調整しやすくしてください。
- **出来事の振動**（常に続く振動より優先する）
  - 光を取った：短く2回
  - ゴール：長めのリズムで、ご褒美感のあるもの
  - 墜落：強く長く1回
  - 地面に近い（赤）：警告音と同じリズムの短い振動を繰り返す
- 一時停止・画面を離れたとき・墜落やゴールの後は、すぐ止めます（`navigator.vibrate(0)`）。

### 5. 振動がセンサーに混ざらないかの確認

- スマホ自体が揺れるので、傾きセンサーの値がぶれる可能性があります（推測・未確認）。
- 検証用に、センサーの値のぶれの大きさ（たとえば直近1秒の、機首・旋回の入力角度の揺れ幅）を画面の検証表示に出してください。振動のオン・オフで比べられるようにします。

### 6. 設定と記録

- 調整パネルに、次の設定を追加します。
  - 音のオン・オフ、音量（初期値は控えめ）
  - 効果音のオン・オフ
  - 振動のオン・オフ、振動の強さ（倍率）、通常飛行の震えのオン・オフ
- 振動に対応していない端末（iPhoneなど）では、振動の設定を隠すか、使えないことが分かる表示にします。
- 記録とコピーに、音と振動の設定、センサーのぶれの値（平均・最大）を含めます。

### 7. 版番号・記録

- 版番号を上げ、README と `docs/verification-v01xx.md` を更新します。
- 処理の重さを測ってください。SCC側と同じ考え方の値を検証表示に出し、Pixel 9aでの確認は発案者に依頼する形で記録します。

## 変えないもの

- 操縦の入力、物理計算、表示モード、視点、レーダー。
- SCCシミュレーターのチップの計算（写したファイルの中身）。

## テスト

- 単体テスト：
  - 迎え角・出力・速度から、振動の強さと効果音の値を計算する部分（境界、無効な値）。
  - 出来事の振動・音が、常に続くものより優先されること。
  - 一時停止で、振動と音が止まること。
  - 効果音用PSGへの書き込みが、BGM用に影響しないこと。
- ブラウザーテスト：
  - 開始ボタンを押す前に、音と振動が出ないこと。
  - `navigator.vibrate` が無い環境でも、エラーにならないこと。
  - 設定のオン・オフ、保存、記録への反映。
- 既存のテストはすべて通ること。
- 音の聞こえ方、振動の感じ方、センサーへの影響、処理の重さは、PCでは確認できません。Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 音色、音の高さ、音量、振動のパターン・強さ・周期、迎え角の境目の値。
- 効果音のチャンネルの割り当て、優先順位、設定の項目と配置。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- SCCシミュレーターのチップの計算を変えること。
- ライセンス表示（NOTICE）を外すこと。
- 端末の外へ情報を送る処理の追加（設定と記録は端末内だけで扱う）。
- 開始ボタンを押す前に音や振動を出すこと。
- センサーの許可の取り方と、停止・再開時に速度と出力を0へ戻す安全側の動作。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
