# twist 次の版の指示：旋回の強さの見直し・ステージの拡大・曲がりがいのある3コース

作業中の版（案内とHUDの英語化など）があれば、その次の版として出してください。スピード感とアフターバーナーは、この次の版で扱います（別紙）。

## 背景（なぜ直すか）

v0.1.24の実機の記録は、全体で約12秒、各区間3秒前後でした。発案者の感想は「コースが単調すぎる構成になった」です。

原因はコードで確認済みです。

1. **速度が上がり、曲がれる円が大きくなった**
   - v0.1.24で、巡航速度10m/s・最高速度30m/sになりました（`flight-physics.js`）。
   - 旋回は今までどおり `重力(3) × tan(翼の傾き) ÷ max(速度, 6)`（上限0.8rad/s）で計算しています（`stage.js` の `flightYawForBank`）。
   - 翼35°のとき、曲がれる円の半径は、10m/sで約48m、30m/sで**約430m**です。ステージは前後左右110m（`stage.js` の `clamp(..., -110, 110)`）なので、速く飛ぶと中で曲がりきれません。
2. **配置の決まりに下限がなかった**
   - 前の指示は「曲がりきれること」だけを条件にしていたため、ほぼまっすぐの配置が合格しました（`course.js` の今の配置は、左右のずれが最大8m）。

### 前提の変更（前の指示からの変更点）

- 前の指示（コースの配置と出口）では、「飛行の仕組み（旋回の計算・重力）は変えない」としていました。
- その後、速度そのものが大きく上がったので、**今回は旋回の強さを見直します**。発案者の了承済みです。
- 今の重力3m/s²は、初期の検証用のゆっくりした設定でした。現実の重力（9.8m/s²）に近づけることは、実機の手応えにも近づく方向です。

## やること

### 1. 旋回の強さを、速度に見合うように上げる（A）

- 旋回の計算に使う値を、揚力や落下に使う重力とは別の「**旋回の強さ**」（例：`turnGravity`）として分けます。
- 初期値は **9.8**（現実の重力相当）を目安にします。翼35°・10m/sで、半径約14mになります。
- 旋回の速さの上限（今は0.8rad/s）も、新しい強さに合わせて見直してください。低速で上限に当たって曲がれない、ということが起きないようにします。
- 調整パネルに「旋回の強さ」を追加し、発案者が実機で変えられるようにします（範囲の目安：3〜15）。早見表（`docs/settings-guide.md`）と画面の説明にも追加します。
- 揚力・落下・失速の計算に使う重力（`gravity: 3`）は、今回は変えません。上昇・下降の手応えまで変わるのを避けるためです。変える必要があると判断した場合は、変える前に理由を書いて質問してください。

### 2. ステージを広げる（B）

- 前後左右110mの範囲を広げます（目安：前後左右300〜400m）。速度30m/sでも、ステージの中で曲がって戻れる広さにします。
- 広げたことで、地面・遠景・霧・目印・雲・中央の塔・レーダーの範囲の初期値が不自然にならないよう、合わせて調整します。霧の距離は、広さに合わせて伸ばします。
- ステージの端は、見えない壁で急に止めるのではなく、端が近いことが見て分かる形にします（例：嵐の雲の壁。今後の浮島の世界の構想に合わせた見た目）。端に近づいたら、警告と、戻る方向の案内を出します。
- 描画の重さ（`frameCpu` の平均・最大）を、広げる前後で比べて記録してください。今は平均約2.6ms、最大約10〜19msです。

### 3. 配置の決まりに「下限」を入れ、曲がりがいのあるコースにする（C）

`course.js` の配置の検証（今は「曲がりきれるか」だけ）に、次を加えます。

- **曲がり角の難しさ**：各曲がり角で、機体が曲がれる限界の何割を使うか（使用率）を計算します。曲がりきれない（使用率が10割を超える）配置は今までどおり失敗にし、加えて、**使用率が下限より小さい曲がり角ばかりの配置も失敗**にします。
- **判定の条件**：速度は巡航（10m/s）と、その2倍（20m/s）の2通り。翼の傾きは30°。旋回の強さは1.の初期値。
- **コースの条件（目安）**
  - 45°以上の曲がり角を、決まった数以上入れる。
  - 上昇と下降の両方を含める（1区間の高さの変化は、今までどおり無理のない範囲）。
  - 巡航速度で飛んだときの1周の目安時間を、コースごとに決めた範囲に収める。
  - 光と出口が、構造物や地面に隠れない位置にある。
- 判定の数値（使用率の幅、曲がり角の数、目安時間）は、1か所にまとめ、後で調整しやすくしてください。

### 4. 3つのコースを用意し、選べるようにする

| コース | 目標の数（目安） | 曲がり角の使用率（目安） | 1周の目安（巡航速度） |
|---|---|---|---|
| やさしい | 3〜4 | 3〜6割 | 30〜45秒 |
| ふつう | 5〜6 | 4〜8割 | 45〜75秒 |
| むずかしい | 7〜8 | 6〜9割（高さの変化も大きめ） | 60〜90秒 |

- 3コースとも、3.の決まりに合格すること。
- 開始画面と一時停止画面で選べるようにします。選んだコースは端末に保存します。
- 目標の数が増えても、HUD（TGT 1〜n）、目標高度の目印、レーダー、案内（フライトディレクターなど）、区間ごとの時間、出口の発見時間が正しく動くようにします。今の `BEACONS.length` を前提にした処理を、コースのデータから決まる形にしてください。
- 探索モードでも同じコースを使う場合は、探索モードで取れることも確認します。難しければ、探索モードは今の配置のままにして構いません（理由を記録）。
- 今の一直線のコース（v0.1.24）は、比較用として残しても構いません。

### 5. 記録

- 記録とコピーに、コースの名前、旋回の強さ、ステージの広さを追加します。
- 区間ごとの時間は、コースの目標の数に合わせて増やします。

### 6. 版番号・記録

- 版番号を上げ、README、`docs/settings-guide.md`、`docs/verification-v01xx.md` を更新します。3コースの座標と、検証の数値（各曲がり角の使用率、目安時間）を一覧にして記録します。

## 変えないもの

- 揚力・落下・失速の計算と、その重力の値。
- 巡航速度・最高速度（スピード感の見直しは次の版で扱う）。
- 光・出口を取れる判定の大きさ。
- 操縦の入力、音、振動、BGM。

## テスト

- 単体テスト：
  - 旋回の強さを変えたときの、旋回の速さと半径の計算。上限の扱い。
  - 配置の検証：曲がりきれない配置が失敗すること。**まっすぐすぎる配置（v0.1.24の配置）が失敗すること**。3コースがすべて合格すること。
  - 目標の数が3以外のコースで、収集・出口の開放・区間ごとの時間が正しく動くこと。
  - ステージの端の判定と警告。
- ブラウザーテスト：
  - 3コースを選んで開始でき、疑似操作で完走できること。
  - 広げたステージの端で、警告と戻る方向の案内が出ること。
  - HUD・レーダー・案内が、目標の数が多いコースでも正しいこと。
  - 390×844・360×640・844×390で、表示が重ならないこと。
- 既存のテストはすべて通ること。
- 実機での曲がりやすさ、コースの面白さ、描画の重さは、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 旋回の強さの初期値と範囲、旋回の速さの上限。
- ステージの広さ、端の見た目、霧の距離。
- 3コースの配置、目標の数、使用率の幅、目安時間、コースの名前。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 揚力・落下・失速の重力を変えること。
- 光・出口を取れる判定を大きくすること。
- 端末の外へ情報を送る処理の追加（設定と記録は端末内だけで扱う）。
- 開始ボタンを押す前に音や振動を出すこと。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
