# twist 次の版の指示：BGMの作り直し、操縦席視点の見やすさ、目標高度の目印

PWA対応の版が終わってから取りかかってください。この版では、独立した3つの改修を行います。

- A. BGMをアップテンポでハードな曲に作り直す
- B. 操縦席視点（`camera=cockpit`）の見やすさを改善する
- C. 次の目標の高さを示す目印を追加する

一部だけが先に終わった場合は、分けて公開しても構いません。記録には、どれを反映した版かが分かるように書いてください。

---

# A. BGMの作り直し


## 背景（なぜ作り直すか）

発案者の感想は、「かなり遊べる状態になったが、BGMは単調で飽きる。アップテンポでハードな雰囲気にしたい」です。

今の曲（`tools/generate-music.mjs` が作る `public/music/flight.mid`「ひかりの航路（仮）」）が単調に聞こえる理由は、コードで確認済みです。

- テンポ128で、24小節（約45秒）を繰り返している。
- メロディは、7音の同じリズム（`rhythm=[0,.5,1,1.5,2.5,3,3.5]`）を全小節で使っている。
- 和音とベースは、4小節の同じ形をずっと繰り返している。
- ドラムも全小節同じ形で、フィル（区切りの小節での変化）がない。
- イントロ、サビ、ブレイクなど、曲の展開がない。

## やること

### 1. 飛行中の曲を作り直す（オリジナル曲）

- **テンポ**：150〜170程度。
- **雰囲気**：アップテンポでハード。短調を基本にし、緊張感と疾走感を出します。1980年代のMSXのシューティングゲームのような、SCCらしい攻めた音を目指します。
- **展開**：イントロ → Aメロ → Bメロ → サビ → ブレイク（静かになる区間）→ ループ、のように、区間ごとにはっきり変化を付けます。ループの長さは60〜90秒程度です。
- **SCC 5チャンネルの使い方の例**（実機のSCCと同じ5チャンネルの範囲で）
  - メロディ
  - 対旋律、または速いアルペジオ（和音を素早く分散して鳴らす、SCCらしい手法）
  - 和音（リズムを刻む）
  - ベース：8分音符か16分音符で刻み続け、曲を前へ押し出す
  - エコー：メロディを少し遅らせ、音量を下げて重ねる（当時よく使われた手法）
- **ドラム（PSG）**：バスドラムとスネアを強めにし、区切りの小節にフィルを入れます。サビでは密度を上げます。
- 音色（SCCの波形）は、`tracks.json` のパートごとの設定で、ハードな曲に合うものを選んでください。必要なら、波形を新しく作って構いません。
- **既存の曲を写したり、似せたりしないでください**（特定のゲーム音楽のメロディや展開を含む）。

### 2. 飽きにくくする工夫

- 飛行中の曲を**2曲以上**用意し、飛び直すたびに切り替える、または一定時間で切り替えるようにします。どちらにするかは、Codexが判断して記録してください。
- 2曲目は、同じハードな雰囲気の中で、テンポや調を変えて違いを出します。
- 今の「ひかりの航路（仮）」は、比較用として残して構いません（`tracks.json` で選べる形）。

### 3. ゴールの曲

- 新しい曲の雰囲気に合わせて、ゴールのジングル（`clear.mid`）も作り直します。短く、達成感のあるものにします。

### 4. 差し替えやすさは保つ

- 曲は、今までどおり `tools/generate-music.mjs`（または同じ役割のスクリプト）で作り、元のデータを残します。
- `tracks.json` の形と、発案者が自作のMIDIファイルに差し替える手順（`docs/music.md`）は変えないでください。曲が増えて設定の形を変える必要がある場合は、手順書も合わせて直します。

### 5. 処理の重さ

- 音の数が増えるので、音の処理の重さ（今の記録で平均約28%、最大約34%）を、変更の前後で比べて記録してください。Pixel 9aでの確認は、発案者に依頼する形で記録します。

### 6. 版番号・記録

- 版番号を上げ、README と `docs/verification-v01xx.md` を更新します。記録とコピーには、鳴らした曲の名前が残るようにします（今の `music` の項目）。

## A の変えないもの

- 操縦の入力、物理計算、表示、振動、効果音。
- SCCシミュレーターのチップの計算と、MIDI再生部分の決めごと。
- 効果音用PSGとBGM用の分離。

## A のテスト

- 単体テスト：生成した曲が、指定のテンポ・長さ・使用チャンネルの範囲に収まること。複数曲の切り替えの決めごと。
- ブラウザーテスト：飛行中の曲が鳴り、決めた条件で切り替わること。ループ位置で正しく戻ること。ゴールのジングルが鳴ること。
- 既存のテストはすべて通ること。
- 曲の聞こえ方は、Pixel 9aでの確認を「未確認」として記録に残してください。

# B. 操縦席視点の見やすさ

## 背景（なぜ直すか）

発案者が操縦席視点で飛んだ感想は、次の2点です。

- 上昇・下降がしづらい。
- 構造物のない場所では、旋回している向きが分かりにくい。遠くに目標物（山や海など）があると解消できるかもしれない。

記録の数字でも、操縦席視点では失速からの復帰補助が多めに働いています（最後の1回で約9.3秒）。

原因は、コードと発案者のスクリーンショット（v0.1.16、縦持ち）で、次のように見ています。

- **遠くに手がかりがない（確認済み）**：`scene.fog` で、物は48m〜156mの間で空の色に溶けます。ステージは前後左右110mまでで、遠くに方向の手がかりになる物がありません。
- **地面がどこも同じ模様（確認済み）**：格子と市松模様は、距離と速さは読めますが、向きの手がかりにはなりません。
- **縦持ちの視野（確認済み）**：390×844では、上下の視野が約84度、左右が約45度です（`computeFieldOfView`）。上下が広いため、機首の角度の変化が画面上で小さく見えます（推測）。
- **景色が見える範囲が狭い（スクリーンショットから）**：上のタイトル・目標カード・レーダーと、下の出力スライダー・ボタンで、画面の上下それぞれ約4分の1が埋まっています。出力はHUDと下のパネルの2か所に重複して出ています。
- **ピッチラダーが多すぎる（スクリーンショットから）**：+15度〜−15度の線が画面全体に広がり、下側の破線が地面の模様と重なって読みにくくなっています。
- **上昇・下降の表示が小さい（スクリーンショットから）**：昇降速度は、高度の目盛り帯の下に「↕+0.0m/s」と小さく出ているだけです。

## やること

### 1. 操縦席視点の画面を広げる（`camera=cockpit` のとき）

- 上のタイトルと目標カードを、小さく1行程度にまとめます。
- 下のパネルは、出力スライダーを細くするか半透明にして、景色が見える範囲を広げます。一時停止・持ち方の合わせ直しのボタンは、押せる大きさを保ちます。
- 出力の表示は、HUDか下のパネルのどちらか1か所にまとめます。
- 他の視点（`overlay`、`chase`）の画面は変えません。

### 2. ピッチラダーを絞る

- 今の機首の角度の前後（初期値±10度）の線だけを表示します。
- 線は中央に寄せて短くし、ラベルは線の端に小さく付けます。
- 水平線より下の破線は、薄くするか細くして、地面の模様と重ならないようにします。
- 表示する範囲は、調整パネルで変えられるようにします。

### 3. 上昇・下降を大きく見せる

- 高度の目盛り帯の横に、昇降速度を示す縦の棒または矢印を付けます。上昇は上へ、下降は下へ伸び、ひと目で分かる大きさにします。
- 進行方向の印（フライトパスマーカー）を少し大きくし、機首の印から離れたときに目立つようにします。

### 4. 上昇の音（バリオ）

- グライダーの計器と同じ考え方で、上昇中は「ピッ、ピッ」と短い音を鳴らし、上昇が速いほど音を高く、間隔を短くします。下降が速いときは、低く長い音にします。
- 効果音用PSGで鳴らします。既存の効果音（警告など）より優先度は低くします。
- 調整パネルでオン・オフできるようにします（初期値はオン）。
- 操縦席視点以外でも使えるようにして構いません。

### 5. 遠景と、向きの手がかり

今後の構想（空に浮かぶ島と遺跡の世界）に合わせた見た目で作ります。

- **遠景**：ステージの外側の遠くに、方角ごとに形の違う大きな浮島や遺跡のシルエットを置きます。霧で消えないようにし、遠さが分かるよう空の色に少し寄せた色にします。360度を囲む背景として、処理を軽く作ってください。
- **中心の塔**：ステージの中央付近に、どこからでも見える高い遺跡の塔を置きます。旋回中の向きの基準になります。当たり判定は、今回は不要です（地面との接触だけが失敗、の今のルールのまま）。
- **太陽**：空に太陽を1つ置きます。
- **雲**：高さの違う場所に、雲をいくつか浮かべます。通り過ぎる雲で、上昇・下降と速さを感じられるようにします。雲には当たり判定を付けません。
- 遠景・塔・太陽・雲は、`view=assisted` で表示します。`view=legacy` は従来のまま残します。
- 既存の4方向の目印（`DIRECTION_LANDMARKS`）や光の見やすさを邪魔しない配置にしてください。

### 6. 操縦席視点の上下の視野（任意の設定）

- 調整パネルに、操縦席視点の上下の視野を変える設定を追加します。初期値は今の計算のまま、範囲は60度〜今の値までです。
- 狭くすると、機首の動きが画面上で大きく見えるようになります。広さとの兼ね合いを、実機で試せるようにします。

### 7. 処理の重さ

- 遠景・塔・雲を足す前後で、描画の重さ（`frameCpu` の平均・最大）を比べて記録してください。今の記録は、平均約2.5ms、最大約22msです。

## B の変えないもの

- 操縦の入力、物理計算、失速からの復帰補助、当たり判定（地面との接触だけ）。
- 外から見る視点（`overlay`、`chase`）の画面の配置。
- レーダー、光の色、振動。

## B のテスト

- 単体テスト：ピッチラダーの表示範囲の絞り込み、昇降速度の棒の長さ、バリオ音の高さと間隔の計算（境界と無効な値）。
- ブラウザーテスト：
  - `cockpit` で上下のパネルが小さくなり、他の視点では変わらないこと。
  - ラダーが機首の角度の前後だけに出ること。
  - 遠景・塔・太陽・雲が `assisted` で表示され、`legacy` では表示されないこと。霧で消えないこと。
  - バリオ音のオン・オフと保存。
  - 390×844・360×640・844×390で、HUD・レーダー・ボタンが重ならないこと。
- 見やすさ、向きの分かりやすさ、バリオ音の聞こえ方は、Pixel 9aでの確認を「未確認」として記録に残してください。

# C. 次の目標の高さを示す目印

## 背景（なぜ入れるか）

発案者の希望は、「次の目標の高度を示す目印を出してほしい。その高さに合わせて飛べば、正しく取れる目印にしたい。設定でオン・オフしたい」です。

今の作り（コードで確認済み）は次のとおりです。

- 光の高さは、10m・18m・12m、出口は7mです（`stage.js` の `BEACONS`、`EXIT`）。
- 光を取れる範囲は、中心から半径3.2m（出口は4m）です（`COLLECT_RADIUS`、`EXIT_RADIUS`）。真横から近づく場合、高さの差がおよそ±3.2m以内なら取れます。
- 高さの表示は「地面まで」の値です。レーダーには、目標が上か下かを示す▲▼がありますが、何m上げればよいかは分かりません。
- 機首を上げてから高度が変わるまでには時間がかかるので、近づいてから高さを合わせても間に合わないことがあります。

## やること

### 1. 高さの目印（全視点で）

- **目標高度の帯**：高さの表示に、次の目標の高さを示す印と、取れる範囲（目標の高さ±取れる半径）の帯を重ねます。
  - 操縦席視点：右の高度の目盛り帯に、印と帯を出します（実際の飛行機の高度計にある「目標高度の印」と同じ考え方）。
  - 外から見る視点（`overlay`・`chase`）：今の「地面まで」の表示か、その近くに、同じ意味の印と帯を出します。
- **高さの差**：「目標 18m ▲+6m」のように、目標の高さと、今の高さとの差を数字で出します。帯の中に入ったら、色を変えて「高さOK」が分かるようにします。
- **早めの合図**：今の昇降速度のままでは、目標に着く前に帯に入れない場合に、上げる・下げる方向の矢印を目立たせます。目標までの距離・速度・昇降速度から計算します。計算の方法は、Codexが判断して記録してください。
- 出口が次の目標のときも、同じように表示します。

### 2. 設定

- 調整パネルに「目標高度の目印」のオン・オフを追加します。初期値はオンです。
- 記録とコピーに、この設定を含めます。
- `view=legacy` では、オンにしても表示しないか、従来の見え方を保つ形にしてください（比較用の見え方を変えないため）。どちらにしたか記録してください。

### 3. 版番号・記録

- README と `docs/verification-v01xx.md` を更新します。

## C の変えないもの

- 光・出口の位置と、取れる半径（目印に合わせて判定を緩めたりしない）。
- 操縦の入力、物理計算、レーダーの▲▼表示。

## C のテスト

- 単体テスト：目標高度・帯・高さの差の計算、帯の内外の判定、早めの合図の計算（境界と無効な値）。
- ブラウザーテスト：
  - 3つの視点で、次の目標に合わせて印と帯が出ること。光を取ると次の目標に切り替わること。
  - 帯の中に入ると表示が変わること。
  - 設定のオン・オフと保存。`view=legacy` での扱い。
  - 390×844・360×640・844×390で、ほかの表示と重ならないこと。
- 実機での分かりやすさは、Pixel 9aでの確認を「未確認」として記録に残してください。

# A・B・C 共通

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- テンポ、調、展開、音色、曲数、切り替え方、ループの長さ、音量のバランス。
- SCCのチャンネルの使い方（5チャンネルを超えて使うかどうかを含む）。
- 目標高度の印・帯・矢印の形、色、置き場所、早めの合図の計算方法。
- 操縦席視点の画面の配置、ラダーの範囲、昇降速度の表示の形、バリオ音の音色・高さ、遠景・塔・雲の形・数・色・距離、視野の範囲。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 既存の曲を写すこと、似せること。
- SCCシミュレーターのチップの計算を変えること。ライセンス表示（NOTICE）を外すこと。
- 開始ボタンを押す前に音を出すこと。
- 端末の外へ情報を送る処理の追加。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
