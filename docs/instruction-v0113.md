# twist v0.1.13 指示：機首の上下を「傾き＝角度」方式にする

## 背景（なぜ変えるか）

現在の飛行機モードでは、2つの操作の性質が違います。

- 旋回（ひねる・回す）は「スマホの傾き＝翼の傾き」です。中立へ戻すと翼も水平へ戻ります。
- 機首の上下は「スマホの傾き＝機首が回り続ける速さ」です（`flightRates` の `pitchRate`）。中立へ戻しても、機首は上を向いたまま残ります。

このため、水平に飛ぶには、プレイヤーが今の機首の角度を覚えておき、逆へ倒して打ち消す必要があります。スマホには中立へ戻すバネの手応えがありません。そのため機首を上げたままになりやすく、失速して真下へ落ちる原因になっていると考えています。v0.1.12の復帰補助は、この症状への対処でした。

今回は、機首の上下も旋回と同じ「傾き＝角度」方式を追加して、今の方式と比べられるようにします。

## やること

### 1. 機首の上下を「角度」で指定する方式を追加する

- URLパラメータ `pitch=angle|rate` を追加します。
  - `angle`（新方式・標準）：スマホ上端の傾きで、機首の**目標角度**を決めます。
  - `rate`（比較用）：v0.1.12までの「回り続ける」方式です。そのまま残してください。
- 開始画面と一時停止画面に、旋回の「ひねる／回す」と同じ形の切替を置きます。切り替えたときの扱い（ステージを最初へ戻すかどうか）は、旋回の切替と同じにします。
- `angle` 方式の動き：
  - 中立範囲3度を超えた傾きを、最大傾き（初期値25度）で機首の最大角度（初期値 **上下とも15度**）になるよう、直線で対応させます。
  - スマホを中立へ戻すと、機首の目標は0度（水平）です。
  - 機首は目標角度へ、滑らかに追いかけます。追いかける速さは時定数（初期値0.3秒）で決め、回る速さの上限は今の `pitchRate`（0.65rad/s）を目安にします。
  - 実装のヒント：今の機首の角度を `baseOrientation` から求め、`pitchRate = clamp(係数 × (目標角度 − 今の角度), ±上限)` を計算します。これを今の `stage.update` に渡せば、`stage.js` の回転計算をほぼ変えずに済む見込みです。より良い方法があれば、そちらを選んで構いません。
- PCキーのW/Sは、押している間だけ目標角度を最大にし、離すと0度へ戻します。練習用つまみも同じ考え方に合わせてください。

### 2. 実機で値を調整できるパネルを追加する

実機での操作感がまだ確認できていないため、公開し直さずにスマホ上で値を変えられるようにします。

- 一時停止画面に「調整」パネルを置き、スライダーで次の値を変えられるようにします。
  - 中立範囲（初期値3度）
  - 最大傾き（初期値25度。10〜30度）
  - 機首の最大角度（初期値15度。5〜35度）
  - 機首の追従時定数（初期値0.3秒。0.1〜1.0秒）
  - 翼の最大角度（初期値40度）
- 変えた値は、その端末のブラウザーに保存します（`localStorage`。読み書きに失敗しても初期値で動くようにする）。「初期値に戻す」ボタンも置きます。
- 「設定をコピー」ボタンで、今の値・版番号・`pitch` と `steer` の方式を1行の文字列としてコピーできるようにします。実機の結果を報告するときに使います。

### 3. 比べるための記録を画面に出す

- クリア画面と接地停止画面に、次の値を表示します。
  - 開始からの経過時間
  - 接地した回数（「最初から飛び直す」を押しても、同じ挑戦の中なら回数を数え続ける）
  - 失速からの復帰補助が働いた合計時間
  - `pitch` と `steer` の方式、調整パネルの値
- 「設定をコピー」と同じ形式で、これらもコピーできるようにします。

### 4. 版番号・記録

- 版番号をv0.1.13へ上げます。README、公開URL、`docs/verification-v0113.md` も更新します。
- READMEの公開URLは、`pitch=angle`（標準）と `pitch=rate`（比較）の両方を載せます。

## 変えないもの

- 物理計算（`flight-physics.js`）と失速からの復帰補助です。今回は入力の方式だけを変え、効果を切り分けます。補助が不要になったかどうかは、記録（補助の合計時間）を見て次の版で判断します。
- 探索モードの操作と計算です。
- 旋回の2方式（ひねる・回す）と、画面のスロットルです。

## テスト

- 単体テスト：角度への対応（中立範囲・最大・符号・無効な値）、目標への追従（行き過ぎない、上限を超えない）、`rate` 方式が従来と同じ結果になること。
- ブラウザーテスト：`angle` 方式で中立へ戻すと機首が0度付近へ戻る。方式の切替、調整パネルの保存と初期化、記録表示を確認する。
- 既存のテストはすべて通ること。
- スマホ実機での操作感は、今回も「未確認」として記録に残してください。PCでの疑似操作の成功を、実機確認の代わりにしないでください。

## 判断の範囲

- 初期値（角度・時定数など）、スライダーの範囲、ボタンやパネルの配置、文言、色。

- どちらの方式を標準にするか。

**変えないもの（指示があっても確認してから）**
- 端末の外へ情報を送る処理は追加しません（調整値と記録は端末内だけで扱う）。
- センサーの許可の取り方、停止・再開時に速度と出力を0へ戻す安全側の動作は維持します。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
