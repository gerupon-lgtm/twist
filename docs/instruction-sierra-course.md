# twist 次の版の指示：実在の地形をもとにした縮小コース「シエラ縦断（1/50）」— コースのみ

作業中の版があれば、その次の版として出してください。

## 背景（なぜ作るか）

- 発案者が、実在する飛行ルート（カリフォルニア州のカーン渓谷 → オーエンズ・バレー → デスバレー方面 → ユーレカ砂丘）の7つのポイントを用意しました。これを**縮小して**、今のゲームのコースとして飛べるようにします。
- 実寸では1周約196kmあり、超音速でも約10分かかります。今の飛行の計算（巡航10m/s、旋回の強さ9.8）で遊べるよう、**水平方向を1/50に縮小**します。
  - 1/50にすると、1周は約3.9km、区間は約500〜820mになります。10m/sで約6.5分、20m/sで約3.3分です。
  - 区間が長い直線になるので、アフターバーナーの使いどころ（300m以上の直線）が自然にできます。
  - 曲がり角は最大77°で、今の旋回で十分に曲がれます。
- 高さは、縮小すると低くなりすぎるので、**高さだけ2倍に強調**します（地形の可視化でよく使う方法）。

### 今回の範囲（発案者の指定）

- **今回はコース（門の位置と順番）だけ**を作ります。
- 地形（山や谷の形）と、地形との接触の判定は、**次の段階**で作ります。今回は、今の平らな地面のままです。ただし、次の段階で地形を差し込みやすい作りにしておきます（4.）。

## やること

### 1. 座標の変換（計算済みの値）

- 変換のしかた：
  - 水平：Point Aを基準に、緯度・経度の差をメートルに直し（Aの緯度で経度方向を補正する簡易な方法）、1/50にします。東を +x、北を −z とします（今のコースと同じ向き）。
  - 高さ：7点の推定標高の最小値（790m）を基準にし、`(標高 − 790) × 2 ÷ 50 + 10` mとします（高さ2倍の強調。地面から10m上に門を置く）。
- 計算した値（ステージの中心に寄せた後。単位m）：

| ポイント | x | y（高さ） | z |
|---|---|---|---|
| A | -776.1 | 10.0 | 1536.4 |
| B | -866.3 | 24.8 | 1028.4 |
| C | -123.4 | 23.6 | 672.6 |
| D | 168.4 | 22.4 | 13.0 |
| E | 315.8 | 27.2 | -595.0 |
| F | 866.3 | 41.6 | -1098.9 |
| G | 613.6 | 14.8 | -1536.4 |

- 区間の距離（縮小後）と曲がる角度：A→B 約516m／B→C 約822m（右74°）／C→D 約720m（左41°）／D→E 約626m（左10°）／E→F 約740m（右34°）／F→G 約504m（左77°）。
- 変換のスクリプト（緯度・経度・標高・縮尺・高さの強調を入力して座標を出すもの）をリポジトリに置き、上の値を再現できるようにします。後で縮尺や強調を変えるときに使います。

### 2. コースとして追加する

- コース選択に「シエラ縦断（1/50）」を追加します（コースIDの例：`sierra50`）。
- **開始**：Aの約150m手前（A→Bの向きの逆側）、高さ10mから、A→Bの向き（方位約350°）を向いて始めます。
  - 今のコースの検証が「最初の区間は北向き」を前提にしている場合は、コースごとに開始の向きを持てるようにしてください。HUDの方位（HDG）が実際の方位に近い値になるよう、**コース全体を回転させない**方を優先します。難しければ回転させても構いません（理由を記録）。
- **目標**：A〜FをTGT 1〜6、GをEXITとします。HUDや次の目標の知らせ、地図（ブリーフィング）では、番号に加えて「A」「B」などのポイント名も短く出します（例：`TGT 2 · B`）。
- **ステージの広さ**：このコースは東西約1.7km・南北約3.1kmに広がります。コースごとにステージの広さを持てるようにし、このコースでは余裕を取った広さにします（目安：x ±1100m、z ±1750m）。端の見せ方・警告は今の仕組みを使います。
- **高度の上限**：門の高さは最大約42mで、今の上限45mに収まります。ただし余裕がないので、このコースでは上限を引き上げても構いません（判断を記録）。
- **配置の検証**：今の3コース用の「難しさの帯」（曲がり角の使用率の下限）は、実在の地形をもとにしたこのコースには当てはめず、「実地形コース」として、**曲がりきれること**と**長い直線があること**だけを確認します。
- レーダーの範囲・遠景・霧の距離など、広さに合わせる必要がある値は、このコースのときだけ調整します。

### 3. 見た目（今回は最低限）

- 地形はまだないので、今の平らな地面のままです。ただし、方向の手がかりとして、各ポイントの近くに、ポイント名の付いた目印（柱や旗など）を置きます。
- 遠景に、西側の高い山並み（ホイットニー山の方向）と、東側の山並みのシルエットを置くと、オーエンズ・バレーらしい雰囲気が出ます（任意）。

### 4. 次の段階（地形と接触判定）への備え

- 次の段階で、実際の標高データから地形を作り、地形との接触（墜落）の判定を加えます。そのときに差し込みやすいよう、次の形にしておきます。
  - 「その地点の地面の高さ」を返す関数を1か所に用意し、今は常に0を返すようにします。地面の接触の判定、目標高度の目印の「地面から何m」、地面の模様などは、この関数を通して地面の高さを得るようにします。
  - 各ポイントの元データ（緯度・経度・推定標高）を、コースのデータに残します。
- 今回は、地形のデータの取得や加工は行いません。

### 5. 記録

- 記録とコピーに、コースID、区間ごとの時間（A→B…F→G）、ABを使った区間を含めます（今の仕組みで自動的に増える場合は、それで構いません）。

### 6. 版番号・記録

- 版番号を上げ、README、`docs/verification-v01xx.md` を更新します。座標の変換のしかた、計算した座標、縮尺と高さの強調の値を記録します。

## 変えないもの

- 今の3コースの配置と、その検証の決まり。
- 飛行の計算、取れる判定の大きさ、操縦の入力、案内、HUD、音、振動。

## テスト

- 単体テスト：
  - 変換のスクリプトが、上の表の座標を再現すること（誤差の許容を決めて確認）。
  - このコースが「曲がりきれる」「長い直線がある」の検証に合格すること。
  - 「その地点の地面の高さ」の関数が、今は0を返し、地面の接触や目標高度の目印がこの関数を通っていること。
  - コースごとのステージの広さと、開始の向き。
- ブラウザーテスト：
  - コースを選んで開始でき、疑似操作でA→Gまで完走できること。
  - HUD・次の目標の知らせ・地図に、ポイント名が出ること。
  - ステージの端の警告が、このコースの広さで動くこと。
  - 今の3コースが、従来どおり動くこと。
- 既存のテストはすべて通ること。
- 実機での1周の長さ、ABの使いどころ、描画の重さは、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 縮尺、高さの強調、門の地面からの高さ、開始位置、ステージの広さ、高度の上限。
- ポイントの目印や遠景の見た目、ポイント名の出し方。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 今の3コースの配置と検証の決まりを変えること。
- 取れる判定を大きくすること。
- 速度の表示を、実際のジェット機の速度のように見せる換算をすること（縮尺の世界でも、表示はゲーム内の値のまま）。
- 端末の外へ情報を送る処理の追加。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。発案者が不在の場合は、安全側で仮決めして `docs/open-questions.md` に記録し、先へ進んでください。
