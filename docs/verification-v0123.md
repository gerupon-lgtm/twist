## 実装と判断

- 操縦席/見失い対策のHUDに、カメラ座標と実際の視野で投影した目的物の印、名前・距離・上下差を追加。画面内の正確な位置は中空のひし形、出口は門を表す角形。計器のないHUD領域の外・後方では向きの矢印を出す。後方は後ろと明記し、鏡像投影を使わない。文字は計器/レーダー/ボタンを避ける。正しい投影点が操作欄に隠れる場合は、印の位置をずらしたひし形ではなく、空き位置から本来の投影点へ向く矢印と「表示の奥」を出す。印は描画フレームごと、配置の読取りは既存HUD更新時に行う。ほかの視点の既存案内、legacyは継続する。
- 現在高度を大きくし、目標高度と並べて表示する。目印にも「上に/下に○m」を付け、目標が低く視野にない状況でも高さの差を読めるようにする。
- 出口はassistedで黄色/白の3方向の輪、30px以上の白黄色の目印と地面からの柱。3個取得後に明るく脈打ち、650msの新しい開放音と表示を加える。3個目の取得振動はそのまま、既存のその他の音/振動は変更しない。legacyの元の単一輪・青緑色・門は残す。場所(0,7,-62)・半径4m、光の場所/半径はそのまま。
- 各設定に1〜2行の説明、逆引きの移動/強調、変更した印/初期値を追加。操縦のchangedSettingsと、feedback内のchangedSettingsをコピーへ含める。項目別の履歴/初期化はv0.1.22を継続。HTML早見表はdocs/settings-guide.mdからビルドし、端末内のゲーム一式だけで読める。外部送信や外部サービスを加えない。
- 早見表は、視野の実際の上限、回す方式の範囲、中立範囲の補正、6m/s以下では旋回を鋭くしすぎず、0では旋回しない点、振動変更後のセンサー影響未確認、項目別の履歴/初期化を現行に合わせた。初期値/範囲自体は変更しない。
- 開始→光1→光2→光3→出口の4区間をルートごとに計時し、未完了はnull/画面では未完了。設定/結果コピーと結果画面に残す。待機・一時停止を除く操作中の実時間を使い、既存の飛行時間も同じ時計へ揃える。判定を観測した描画フレームで区切るため、フレーム間隔程度の誤差がある。物理計算の時間刻み/上限は変更しない。リトライ/リセットで区間を最初から、一時停止/カメラ変更では保持する。
- 大きな傾きによる停止経路として、中立面の法線が手前に向かない姿勢（normal.z≤0.08、単軸約85.4度）を不適切として止める制限を確認した。利用者の停止時の案内は不明のため、今回の実機停止がこの経路か、画面の自動回転による経路かは未特定。センサーの故障を確認したわけでもない。角度制限の一時停止を除去し、直前の有効な角度を保って操作を続け、戻せば再追従する。最大舵/加速の既存上限、無効な3軸値/非表示/実際の画面回転時の停止、センサー許可は継続する。コピーに保持状態と最後の停止理由を加える。
- 再開0の資料記載に対しては、既に利用者が選んだ「停止0、手動再開50%・6m/s」を継続する。
- 後からの直接依頼を優先し、音楽を変更しないという資料の一般記述に対しては、既存曲を保持したロック別案のみ追加。「黒曜の翼」はニ短調/156BPM/48小節/73.84608秒。16分の分散音を減らし、伸ばすギター風リード、CC7による減衰、軽い音程の揺れ、2音の伴奏、8分のベース、強い拍のドラムで構成。既存5曲・SCCの計算・再生規則・効果音専用PSG・NOTICEを保つ。

## 実機で残る確認

Pixel 9aでの出口の見つけやすさ、HUDの目印/現在高度/高さ差の読みやすさ、説明の分かりやすさ、大きな傾きでの保持/再追従、ギター風の曲の印象、音/描画の処理負荷は未確認。模擬センサー・WebGLの画素・音源の再生の確認だけで実機の受入としない。iPhone XRは向き固定案内、画面の向きの切替による停止も引き続き実機確認が必要。

1. 開始前の版番号が0.1.23であることを確認し、操縦席/見失い対策で開始する。目標が画面の外や後ろでも、矢印・現在高度・目標高度・上/下の差から進路を選べるか確認する。
2. 3つの光を取り、黄色/白の出口、開放の表示と音、地面からの柱を確認。高い位置から7mの出口へ向かい、ほかの2視点でも見つけやすさを比べる。
3. 結果の4区間とコピーを残す。同じ条件で飛び直し、特に光3→出口を比較する。停止中の待ち時間は区間に入らない。
4. 大きく傾けた後に戻し、停止せず再び追従するか確認する。停止した場合は案内文とコピーのinput.lastPauseReason、画面操作へ変わった場合はinputの履歴を残す。画面の自動回転は別の停止経路として確認する。
5. 設定を1つだけ変え、変更前/初期値の復元、説明、「こう感じたら」からの移動を試す。別の機首方式・表示へ変えた場合も、その方式の逆引きになるか確認する。
6. ロック曲を1周再生し、リードの印象、細かな音の量、警告音との釣り合い、音切れ/発熱を確認する。以前の曲へ戻して比較し、計測の音源/描画CPUと記録を残す。
