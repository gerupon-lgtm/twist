# twist 次の版の指示：PWA化と、フルスクリーン・開始時の向きでの固定

ほかの作業中の版があれば、その次の版として出してください。

## 背景（なぜ変えるか）

- スマホを傾けたり回したりして操作するゲームなので、画面の自動回転が起きると、表示と操作の基準が崩れます。特に `display=fixed` では、ブラウザーが画面の縦横を切り替えると見え方が乱れます。
- 公開用のサブドメイン `https://twist.sikumilab.com/` を用意しました。すでにv0.1.15が表示されることは確認済みです。
- ホーム画面に追加して起動できるようにし（PWA化）、フルスクリーン表示と、開始時の向きでの固定を目指します。

## できること・できないこと（前提）

端末とブラウザーによって、できることが違います。

| | Android（Chrome） | iPhone（Safari） |
|---|---|---|
| ホーム画面に追加して起動 | できる | できる（共有メニューから手動で追加） |
| フルスクリーン（上下のバーを消す） | できる（`display: fullscreen`） | できない。上のステータスバーは残る（`standalone` 扱い） |
| マニフェストでの向きの固定 | できる（`orientation`） | できない（指定しても無視される） |
| ページ内からの向きの固定（`screen.orientation.lock`） | フルスクリーン中ならできる | できない |

- iPhoneでは、アプリ側から自動回転を止める方法がありません。発案者の判断で、**向きの自動固定はAndroid（Pixel）だけで十分**とします。iPhoneは、端末の「画面縦向きのロック」の案内と、向きが変わったときの一時停止で補えば構いません。
- 発案者の実機は、Pixel 9a（Android・Chrome）と iPhone XR（iOS・Safari）です。両方で確認できるようにしてください。

## やること

### 1. PWAの基本

- Webアプリのマニフェスト（`manifest.webmanifest`）を追加します。
  - `name`：twist、`short_name`：twist（表示名は発案者の指示で変えて構いません）
  - `start_url`：`./?mode=flight&view=assisted&pitch=angle&steer=tilt`（今の標準の組み合わせ）
  - `scope`：`./`
  - `display`：`fullscreen`
  - `orientation`：`any`（向きは開始時に決めるため、マニフェストでは縦・横を指定しない。下の3.を参照）
  - `theme_color`、`background_color`：画面の空の色に合わせる
  - アイコン：192×192、512×512、マスク用（`purpose: maskable`）。既存の `favicon.svg` の雰囲気をもとに作ってください。
- `index.html` に、マニフェストへのリンク、`theme-color`、iPhone用の設定（`apple-touch-icon`、`apple-mobile-web-app-capable`、ステータスバーの見た目）を追加します。
- ビルドは今の `--base=./`（相対パス）のままで、`twist.sikumilab.com` の直下でも、旧URL（`gerupon-lgtm.github.io/twist/`）でも動くようにしてください。

### 2. サービスワーカー（更新が古いまま残らないことを最優先）

- これまでは、更新時に古い画面が残る混乱を避けるため、サービスワーカーを使っていませんでした（README記載）。この方針の理由は今後も守ります。
- ホーム画面への追加を確実にするために、サービスワーカーを置く場合は、**キャッシュしない**（毎回ネットワークから読む）最小のものにしてください。オフラインで遊べるようにはしません。
- サービスワーカーが不要と判断できる場合は、置かなくても構いません。どちらにしたか、理由と、Android・iPhoneで追加できるかの確認結果を記録してください。
- 新しい版を公開したとき、ホーム画面から起動しても新しい版が表示されることを確認してください（画面の版番号で判断）。

### 3. フルスクリーンと、開始時の向きでの固定

縦向き・横向きのどちらでも遊べる今の作りを保ちます。そのうえで、**開始したときの向きに固定**します。

- **Android**
  - 「この持ち方で飛ぶ／始める」を押したときの向き（`screen.orientation.type`。例：`portrait-primary`、`landscape-primary`、`landscape-secondary`）を記録し、その向きそのものに固定します（`screen.orientation.lock(記録した向き)`）。
  - `landscape` のような大まかな指定ではなく、記録した向きをそのまま指定してください。大まかな指定だと、横向きのまま180度ひっくり返ることがあり、操作の基準がずれるためです。
  - 向きの固定はフルスクリーン中でないと効かないことがあります。ホーム画面から起動していない場合は、同じボタンを押したタイミングで先に `requestFullscreen` を試します。
  - 固定やフルスクリーンに失敗しても、遊べるようにしてください（失敗した理由を画面に出す必要はありません）。
  - 「持ち方を合わせ直す」で、今の向きに固定し直せるようにします。一時停止画面から、フルスクリーンと固定を解除できるようにします。
- **iPhone**
  - アプリ側から向きを固定できません。また、iPhoneの「画面縦向きのロック」は縦向きにしか固定できません。
  - 縦向きで遊ぶ場合：開始画面に「画面縦向きのロックをオンにすると遊びやすくなります」と短く案内します。
  - 横向きで遊ぶ場合：ロックを使えないため、遊んでいる最中に向きが変わる可能性があります。
  - どちらの場合も、遊んでいる最中に開始時と違う向きに切り替わったら、一時停止して「開始したときの向きに戻してください」と表示します。戻ったら、持ち方を合わせ直してから再開できるようにします（今のセンサー消失時の停止と同じ、安全側の扱い）。
  - ホーム画面への追加方法（共有メニュー →「ホーム画面に追加」）も案内します。
- 案内文は、端末の種類と、ホーム画面から起動しているかどうかに合わせて出し分けます。不要な案内は出さないでください。
- 探索モードにも同じ扱いを適用して構いません。

### 4. ホーム画面への追加の案内

- Androidでは、ブラウザーが追加の提案（`beforeinstallprompt`）を出せる場合、開始画面に「ホーム画面に追加」ボタンを出します。
- すでにホーム画面から起動している場合は、追加の案内を出しません。

### 5. 引っ越しの注意（ドメインが変わることの影響）

- 調整パネルの設定は、端末のブラウザーにドメインごとに保存されます（`localStorage`）。そのため、旧URLで保存した設定は、新しいドメインでは引き継がれず、初期値に戻ります。READMEに書いておいてください。引き継ぎの仕組みは今回は不要です。
- READMEの公開URLを `https://twist.sikumilab.com/` に変更します。旧URLも動く限り、併記して構いません。

### 6. 記録

- 記録とコピーに、起動のしかた（`"launch":"browser|installed"`）とフルスクリーンかどうか（`"fullscreen":true|false`）を追加します。

### 7. 版番号・記録

- 版番号を上げ、README と `docs/verification-v01xx.md` を更新します。
- Android・iPhoneそれぞれで、何ができて何ができないかを表で記録してください。

## 変えないもの

- 操縦の入力、物理計算、表示モード、視点、レーダー、調整パネルの中身。
- センサーの許可の取り方（ボタンを押したときに許可を求める）。

## テスト

- 単体テスト：端末・起動方法の判定と、案内文の出し分け。
- ブラウザーテスト：
  - マニフェストが読み込まれ、必要な項目がそろっていること。
  - 旧URL（`/twist/` 配下）と、ルート直下の両方の配置で、画面・マニフェスト・アイコンが読み込めること。
  - 縦で開始して横（844×390）に変わったとき、横で開始して縦に変わったときの両方で一時停止し、元の向きに戻すと再開の案内が出ること。
  - フルスクリーンや向きの固定が失敗しても、エラーにならず遊べること。
- 既存のテストはすべて通ること。
- ホーム画面への追加、フルスクリーン、向きの固定は、PCでは確認できません。Pixel 9a と iPhone XR での確認を「未確認」として記録に残し、確認手順を `docs` に書いてください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- アプリ名、アイコンのデザイン、色、案内文、案内を出す場所。
- `start_url` の初期の組み合わせ。
- サービスワーカーを置くかどうか（上の条件を満たす範囲で）。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 古い版がキャッシュに残り続ける仕組みにすること（オフライン用のキャッシュなど）。
- 端末の外へ情報を送る処理の追加（設定と記録は端末内だけで扱う）。
- センサーの許可の取り方と、停止・再開時に速度と出力を0へ戻す安全側の動作。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
