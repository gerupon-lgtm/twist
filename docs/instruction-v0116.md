# twist v0.1.16 指示：視点の切替（外から見る3D視点・コックピット視点）と戦闘機風の外観

## 前提の確定（v0.1.15までの実機結果）

- 機首は `pitch=angle` を標準、`pitch=rate` を比較用として残します（変更なし）。
- `display=bank` と `display=fixed` は、どちらも残します（変更なし）。
- v0.1.15の記録（`display=fixed`、`view=assisted`）は次のとおりです。
  - 合計：約418秒、2回飛んで墜落1回、クリア。
  - 最後の1回：約164秒、墜落0回、復帰補助約1.7秒。
  - 1回目（計算値）：約254秒で墜落、復帰補助約18.8秒。
- 発案者の希望は次の3点です。
  - 戦闘機のように、コックピットから見た視点で遊びたい。HUDに高度や速度の目盛りがあるイメージ。
  - 外から見る視点では、旋回や上昇・下降のときに、少し違う角度から自機が見えるようにしたい。
  - 自機を、超音速戦闘機（Su-27系）に**似た雰囲気**のカッコいい外観にしたい。

## 今の作りの確認（コードで確認済み）

- 世界を写すカメラ（`camera`）は、自機の位置に置かれています。地面を見る補助が働くときだけ、少し後ろ・上に下がります。
- 自機は、世界とは別の場面（`craftScene`）に、遠近感のないカメラ（`OrthographicCamera`）で重ねて描いています。形は、平たい矢印形を押し出したもの（`hullShape` と `ExtrudeGeometry`）で、上から見た向きに置かれています。
- つまり今の見え方は、「操縦席の位置から見た世界」の上に、「上から見た自機の絵」を重ねたものです。自機を外から立体的に見ているわけではありません。

このため、次のように進めます。

- コックピット視点は、今の世界カメラに近いものです。重ねている自機を消して、HUDを足す形で作れます。
- 外から見る3D視点は、自機の立体模型を世界の中に置き、カメラを後ろ・少し上に下げる、新しい作りになります。

## やること

### 1. 視点の切替を追加する

- URLパラメータ `camera=overlay|chase|cockpit` を追加します。
  - `overlay`（現行・標準）：v0.1.15の見え方をそのまま残します。
  - `chase`（新規）：自機の立体模型を、後ろ・少し上から見る視点です。
  - `cockpit`（新規）：操縦席から見る視点です。自機は描きません。
- 開始画面と一時停止画面に、ほかの切替と同じ形で置きます。切り替えたときは、位置と向きを保ったまま、表示だけを変えます。
- 視点は表示だけを変えます。操縦の入力、飛行の計算、当たり判定には影響させません。

### 2. `chase`（外から見る3D視点）

- 自機の立体模型（下の4.）を世界の中に置き、カメラを自機の後ろ・少し上に置きます。距離と高さは、画面で自機が今と同じくらいの大きさに見えるよう決めてください。
- **遅れて追うカメラ**：カメラが自機の向きを少し遅れて追いかけます。これで、右旋回では自機の左側面が、上昇では背中側が少し見えます。
  - 遅れの大きさ（時定数）は、調整パネルで0〜0.5秒の範囲で変えられるようにします。初期値は0.15秒程度で、0のときは遅れなしです。
  - 遅れは、上下・左右の向きにだけ使います。
- **翼の傾きの見せ方**は、`display` の決まりに従います。
  - `display=bank`：自機が翼の分だけ傾いて見えます。
  - `display=fixed`：自機は人から見て上向きのまま、景色（地平線）が傾きます。スマホを面内で回したときの補正も、v0.1.14と同じです。
- 地面を見る補助は、`chase` でも使えるなら残してください。

### 3. `cockpit`（コックピット視点）とHUD

- カメラを操縦席の位置に置き、自機の模型は描きません。
- 地面を見る補助は使いません（操縦席からは成り立たないため）。地面との近さは、HUDの高度表示、既存の警告、レーダーで知らせます。
- **HUDの構成**（戦闘機のヘッドアップディスプレイの雰囲気）
  - 左：速度の目盛り帯（m/s）と、今の数値
  - 右：地面までの高さの目盛り帯（m）と、今の数値。昇降速度も小さく添える
  - 上：方位の目盛り帯
  - 中央：水平線と、5度ごとの機首角度の横線（ピッチラダー）。上は実線、下は破線などで区別する
  - 中央：機首の向きの印と、実際に進んでいる方向の印（失速すると2つが離れて見えることで気づける）
  - 下：エンジン出力（%）
  - 既存の「地面まで」の警告や失速の復帰補助の表示は、HUDの中に収めてください。
- **色と線**：昔ながらの緑系を基本にします。空の水色と地面の茶色のどちらの上でも読めるよう、細い暗い縁取りを付けます。スマホの小さな画面でも読める太さにしてください。
- **回す・回さないの区別**（v0.1.14で決めた「HUDは回さない」からの変更点です）
  - 水平線、ピッチラダー、進んでいる方向の印は、景色に重ねて意味を持つものなので、景色と一緒に回します。カメラの画角（`fieldOfView`）と合わせて、実際の水平線と一致させてください。
  - 速度・高度・方位の目盛り帯、出力、警告、ボタン、レーダーは回しません。
- 画面の下側の既存の操作量表示（入力角度など）は、`cockpit` では見やすさを優先して、まとめたり小さくしたりして構いません。

### 4. 自機の外観を戦闘機風にする

- **実在機の再現ではなく、オリジナル機体**として作ります。参考にする雰囲気は、Su-27系のような双発の大型戦闘機です。
  - 2基のエンジンと、後ろの2つの噴射口
  - 少し外側へ傾いた2枚の垂直尾翼
  - 主翼の付け根から機首へなめらかに伸びる張り出し
  - 長く細い機首と、泡のような形の操縦席の覆い
  - 後退した主翼と、水平尾翼
- 実在機の名前、国籍マーク、部隊マーク、機体番号は入れません。
- 形は、Three.jsの基本形状や押し出し形状を組み合わせた、軽い多角形の模型で作ります。外部の模型ファイルを使う場合は、自作したもの、または商用利用もできる明確なライセンスのものに限り、出典を記録してください。
- **見やすさ**：空の水色、地面の茶色、新しい光の色（マゼンタ系）の、どれとも混ざらない配色にします。例：明るい灰色の機体に、暗い色の差し色。後ろから見て細くなりすぎないよう、尾翼や噴射口で輪郭が読み取れるようにしてください。
- **演出**：エンジン出力に合わせて、噴射口の光の強さや長さを変えます（出力0%では消える）。
- `chase` で使う立体模型と、`overlay` で上から見た自機の形を、同じデザインにそろえてください。`overlay` の見た目を新しい外観に合わせるのは構いません。ただし、上から見て機首と左右がはっきり分かることは保ってください。

### 5. 記録

- 記録とコピーに `"camera":"overlay|chase|cockpit"` を追加します。
- `chase` 以外では、遅れの時定数を `inactiveSettings` に入れます。

### 6. 版番号・記録

- 版番号をv0.1.16へ上げます。README、公開URL、`docs/verification-v0116.md` も更新します。
- READMEには、3つの視点の公開URLを載せます。

## 変えないもの

- 操縦の入力、物理計算、失速からの復帰補助です。
- `camera=overlay` の見え方（自機の外観の更新を除く）です。
- レーダー、光の色、`view=legacy` です。
- 探索モードです（視点の切替は飛行機モードだけで構いません）。

## テスト

- 単体テスト：
  - `chase` のカメラの遅れが、時定数0のときは遅れなく、正のときは行き過ぎずに追いつくこと。
  - HUDの目盛りの値（速度・高度・方位・機首角度）が、飛行の状態と一致すること。
  - ピッチラダーと水平線の位置が、カメラの画角と機首の角度から正しく計算されること。
- ブラウザーテスト：
  - 3つの視点の切替で、位置と向きが変わらないこと。
  - `chase` で旋回したとき、自機が少し斜めから見えること。`display=bank` と `fixed` で翼の傾きの見せ方が決まりどおりであること。
  - `cockpit` で自機が描かれず、HUDの水平線が景色の地平線と重なること。`display=fixed` でスマホを面内で回すと、水平線は景色と一緒に回り、目盛り帯は回らないこと。
  - 出力を変えると噴射口の光が変わること。
  - 390×844・360×640・844×390で、HUD・レーダー・ボタンが重ならないこと。
  - `overlay` が従来どおり動くこと。
- 既存のテストはすべて通ること。
- スマホ実機での見やすさ、酔いやすさ、操作感は「未確認」として記録に残してください。PCでの確認を、実機確認の代わりにしないでください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 自機の形・色・大きさ、噴射口の演出、カメラの距離・高さ・遅れの初期値。
- HUDの色、線の太さ、目盛りの配置と間隔、表示する項目、文言。
- どの視点を標準にするか。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 実在機の名前、国籍マーク、機体番号を入れること。実在機の形をそのまま写すこと。
- 端末の外へ情報を送る処理の追加（設定と記録は端末内だけで扱う）。
- センサーの許可の取り方と、停止・再開時に速度と出力を0へ戻す安全側の動作。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
