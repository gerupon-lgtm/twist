# twist 次の版の指示：目標を探さなくても向かえる案内（フライトディレクターなど）／HUD表記の英語化

作業中の版（コースの配置・出口の区別など）があれば、その次の版として出してください。

## 背景（なぜ入れるか）

発案者の実機での感想は、「旋回させるのに、目標物を探していると操作が分からなくなってしまう」「HUDは少し直してもらったが、まだ見つけられない」です。試作中なので、分かりやすさが期待できるものは取り入れたい、という方針です。

v0.1.23のスクリーンショット（操縦席視点、縦持ち）と、コードで確認したことは次のとおりです。

- **次の目標が画面の横幅の外にある**：光1（0, 10, 0）から見て、光2（16, 18, -24）は右に約34°・約11m上にあります。縦持ちでは左右の視野が約45°（中央から左右に約22°ずつ。`computeFieldOfView`）なので、光1を通り抜けた瞬間、光2は必ず画面の右外にあります。
- **画面外の目印が画面の中央付近に出ている**：「光2・表示域外」の文字と矢印が、画面の端ではなく中央付近（正面の門の上）に重なり、そこに光があるように見えます。左右の目盛り帯を避けた結果、内側に寄りすぎていると見ています（推測）。
- **方位の目盛りに目標の向きがない**：向きは、目標カードの「右・上」という文字と、レーダーでしか分かりません。
- **探しながら操縦する負担**：目標を探すことに気を取られると、手の傾きへの注意が抜け、中立の手応えがないスマホでは傾きがずれていきます（推測）。

## 方針

- 「目標を探す」作業を、「**画面の印に合わせる**」作業に置き換えます。
- 下の案内は、それぞれ調整パネルでオン・オフできるようにします。どれが効いたかを、発案者が実機で比べられるようにするためです。初期値はすべてオンです。

## やること

### 1. フライトディレクター（目標へ向かう輪）

本物の飛行機にある、「この方向へ機体を向ければよい」と示す計器と同じ考え方です。

- HUDに、**進む方向の目安となる輪**を1つ出します。プレイヤーは、**進行方向の印（フライトパスマーカー）をこの輪に重ねる**だけで、次の目標へ向かえるようにします。
- 輪の位置は、次の目標の方向（左右）と、目標高度の目印で使っている高さの情報（上下）から決めます。
  - 目標が大きく横や後ろにあるときは、輪をそのまま目標の方向に置くのではなく、**今の進行方向から一定の角度（目安：左右15°・上下10°）の範囲**に置きます。輪を追いかけていれば、自然に目標の方へ曲がっていく形にします。
  - 上下の目安は、機首の最大角度の設定と失速の始まり（翼に当たる風の角度20°）を超えない範囲にします。輪を追って失速しないようにするためです。
  - 曲がりきれない近さのときは、いったん回り込む向きへ輪を導くなど、無理な急旋回を求めない動きにしてください。
- 輪に進行方向の印が重なっている間は、輪の色を変えるなど、「合っている」ことが分かるようにします。
- 操縦席視点では、HUDの一部として表示します。外から見る視点（`chase`・`overlay`）でも表示できるようにします。
- 輪の動きはなめらかにし、細かく揺れないようにします。

### 2. 方位の目盛りに目標の印を出す

- 上の方位の目盛りに、次の目標の向きを示す印（▼など）を付けます。印が中央に来るまで曲がれば、目標の方を向くことになります。
- 目標の向きが目盛りの範囲の外にあるときは、目盛りの左右の端に「→34°」のように、向きと角度を出します。

### 3. 画面外の目印を、画面の本当の縁に出す

- 目標が画面の外にあるとき、矢印と距離を、**目標の方向にある画面の縁**に表示します。中央付近には出しません。
- 左右の目盛り帯やレーダーと重なる場合は、それらの外側（画面の縁側）に置くか、重なっても読めるように表示します。
- 矢印は今より大きくし、ひと目で方向が分かるようにします。

### 4. 次の目標の向きを先に知らせる

- 光を取った瞬間に、次の目標の向き（例：「次は 右34°・上11m」）を短く大きく表示します（1〜2秒）。
- 取った直後に、どちらへ曲がり始めればよいかが分かるようにするためです。

### 5. 音で向きを知らせる（イヤホン向け）

- 次の目標の方向から聞こえるように、短い案内音を左右に振り分けて鳴らします（目標が右なら右から）。
- 目標の方を向くほど、間隔を短くするなど、近づいていることが分かる音にします。
- 効果音用PSGで鳴らし、警告やバリオより優先度を低くします。音色と鳴らし方は仮の値で構いません。
- PSGの出力を左右に振り分けるのが難しい場合は、理由を記録したうえで、別の方法（Web Audioの左右の振り分けなど）を使って構いません。

### 6. HUDの表記を英語中心にする

発案者の希望で、HUD（飛行中に画面に重ねて出す表示）の表記を、戦闘機のHUDのような英語の略語中心にします。

**対象**
- 操縦席視点のHUD、画面上の目標の名札、画面外の目印、目標カード（画面上部の「光 1 13m 正面・上」の部分）、目標高度の目印、レーダーの文字、飛行中の警告・合図の文字。
- 1〜5で新しく追加する表示も、この表記に合わせます。

**対象外（日本語のまま）**
- 開始画面、一時停止画面、調整パネル、説明・ヘルプ、ボタン（一時停止、持ち方を合わせ直す、計測など）、結果画面の説明文。

**表記の対応（案）**

| 今の表記 | 新しい表記 |
|---|---|
| 光 1／光 2／光 3 | TGT 1／TGT 2／TGT 3 |
| 出口 | EXIT |
| 速度 m/s | SPD m/s |
| 現在高度 m／地面まで m | ALT m |
| 昇降速度（↕ m/s） | V/S m/s |
| 方位の目盛り | HDG |
| 出力 | THR |
| 目標（高度）18m | TGT ALT 18m |
| 上に6.0m／下に〜m | ▲ +6.0m／▼ −〜m |
| 高さOK | ALT OK |
| 早めに▲ | CLIMB（下げる場合は DESCEND） |
| 表示域外／後ろ | 文字は使わず、目標の方向を指す矢印で示す（後ろの場合は矢印が後方を指す） |
| 正面・上、右・上、左の後ろ・上 など | 文字は使わず、**目標の方向を指す矢印**（目標カードにある、向きが回る矢印と同じ考え方）と、上下の ▲▼ で示す |
| 機首 ＋ 進行方向 ◎（凡例） | NOSE ＋ FPM ◎ |
| 地面との間隔などの警告 | TERRAIN（危険が高いときは PULL UP） |
| 失速の警告 | STALL |
| 出口が開いた合図 | EXIT OPEN |
| 次の目標の知らせ（4.） | NEXT TGT 2 ＋ 方向の矢印 ＋ 34° ▲11m |
| レーダーの「進行方向」 | TRK |

- **方向は、言葉ではなく矢印で示すことを基本にします**（発案者の意見：「矢印も出せば、日本語でなくても分かる」）。左右・前後・上下を、矢印と ▲▼ だけで読み取れるようにしてください。
- 出口は、今後のコースの「門」と区別するため、GATE ではなく **EXIT** にします。
- 表の中で迷う部分は、実際の航空機の表記に近いものをCodexが選んで構いません。選んだ表記は一覧にして記録してください。

**分かりにくさへの配慮**
- 調整パネルの説明（ヘルプ）に、略語の一覧と日本語の意味を載せます（例：FPM＝進行方向の印、V/S＝昇降速度）。
- 調整パネルに「HUDの表記：英語／日本語」の切替を追加します（初期値は英語）。日本語では今までどおりの表記に戻します。
- 記録とコピーの項目名・値は変えません（記録の比較を続けるため）。

### 7. 設定と記録

- 調整パネルに、1〜5のそれぞれのオン・オフを追加します。HUDの表記の切替（6.）も追加します。
- 記録とコピーに、各案内のオン・オフと、**区間ごとの「目標が画面に入るまでの時間」**を追加します。区間ごとの時間と合わせて、案内の効果を比べるためです。

### 8. 版番号・記録

- 版番号を上げ、README と `docs/verification-v01xx.md` を更新します。輪の位置の計算方法も記録します。

## 変えないもの

- 操縦の入力、物理計算、光・出口の位置と取れる判定。
- 目標高度の目印、レーダー、BGM、振動。

## テスト

- 単体テスト：
  - フライトディレクターの輪の位置の計算（目標が正面・横・後ろ・上・下・近すぎるとき。範囲の制限。無効な値）。
  - 方位の目盛りの印の位置と、範囲外の表示。
  - 画面外の目印が、画面の縁に置かれること。
  - 案内音の左右の振り分けと、間隔の計算。
- ブラウザーテスト：
  - 疑似操作で、進行方向の印を輪に重ね続けると、回り込みすぎずに次の目標へ到達できること。
  - 光を取った直後に、次の目標の向きが表示されること。
  - 各案内のオン・オフと保存、記録への反映。
  - HUDの表記が英語の略語になり、切替で日本語に戻ること。開始画面・一時停止画面・調整パネルは日本語のままであること。
  - 英語表記で、文字が切れたりほかの表示と重なったりしないこと。
  - 390×844・360×640・844×390で、ほかの表示と重ならないこと。
- 既存のテストはすべて通ること。
- 実機での分かりやすさ、案内音の聞こえ方は、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- HUDの略語の選び方と、日本語表記を残す範囲。
- 輪の形・色・大きさ・動きの範囲、方位の印の形、画面外の矢印の形と大きさ、次の目標の知らせ方、案内音の音色と鳴らし方。
- 各案内の初期値（オン・オフ）。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 光・出口を取れる判定を大きくすること。
- 案内の都合で、操縦の入力や物理計算を変えること（自動で曲がる・自動で上昇するなどの自動操縦）。
- 端末の外へ情報を送る処理の追加（設定と記録は端末内だけで扱う）。
- 開始ボタンを押す前に音や振動を出すこと。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。
