# v0.1.20 ハードBGMへの改訂（追加資料A）

[指示資料](instruction-next.md)のAを実装する。PWA版v0.1.19の公開・50件の公開ブラウザー確認後に着手。Bの操縦席改善はv0.1.21で続ける。

## 曲と切替

- 独自に手で組んだフレーズから「蒼穹突破」160BPM・イ短調基調・72秒と「遺跡の閃光」168BPM・ニ短調基調・約68.571456秒を生成。どちらも48小節でイントロ4、主題12、展開8、サビ16、静かな区間8。リズム、音域、分散和音/ベースの密度、ドラムの密度を変え、区切りでフィルを入れる。既存曲や特定作品の旋律・展開は参照しない。
- SCCのメロディ/分散和音/短い和音の1音/ベース/遅らせたエコーで同時5音以内。のこぎり波・矩形波・短いパルス波を使用。ベースとエコーは同じ波形を基本とし、4/5音目の波形共有は変更しない。ドラムのPSGは効果音と分離を保つ。
- ゴールは160BPM・3秒の「突破の凱歌」。旧45秒曲はflight-legacy.midとcomparison設定に残す。チップ・MIDI parser/プレイヤーの元コード・NOTICEは変更しない。
- 飛び直しの1回目/2回目/3回目で曲1/曲2/曲1と交互にする。飛行時間の途中での切替より、区切りが分かりやすいため採用。一時停止・合わせ直し・入力方式変更は同じ回のため同じ曲の先頭へ戻る。新しい挑戦は曲1へリセット。
- tracks.jsonの従来flight/clear形式は残し、任意のflightPlaylistで同じ形の追加曲の順番を指定。省略は従来どおり1曲。個別の追加曲が壊れても利用できる曲へ戻り、ゲームは継続する。再生した全曲名・現在/最後の曲名・回数/使用可能な曲名をコピーへ残す。[差し替え手順](music.md)も更新。
- 生成元tools/generate-music.mjsと4つのMIDIを保存。生成コマンドは明示実行だけで、通常ビルドは作者のMIDIや音楽設定を上書きしない。

## 検証

単体・ブラウザー・レビュー・公開確認は完了後に追記する。曲のデータ上のテンポ/長さ/区間変化と5音上限、単曲の互換、回数での交互選曲、欠損した2曲目の扱いは追加の5単体で成功している。元の音楽11単体も成功。

## 負荷の比較条件

提供資料の音源平均約28%/最大約34%、描画平均約2.5ms/最大約22msは提供された記録で、今回のPCと同じ条件ではない。Pixel 9aでの前後比較は未確認として残す。

PC参考値はWindowsのEdge headless、SwiftShader、390×844、公開版、飛行機/見失い対策/従来視点/50%の直進。同じブラウザーを単独で動かし、2秒の準備後に挑戦をリセットして16秒測る。1秒ごとの音源負荷16点の平均と、アプリ内の最大、frameCpuの平均/最大を記録する。最初の30秒測定はステージ端で水平速度が失われて接地し、途中終了したため比較には使わない。物理や移動範囲を変えず、境界へ達する前の共通区間を選んだ。

数値は測定後に追記する。これはPCでの1回の参考測定で、実端末の処理負荷や音の聞こえ方を代用しない。
