# v0.1.29：輪の急な移動の検証

輪は目標の位置ではなく、実際の進行方向を少しずつ変える案内である。白い印（FPM）は実速度の方向を測った表示なので、輪の都合で移動させない。

利用者から「操縦席でも輪が急に飛ぶ・位置が大きく変わる」と具体化されたため、v29の表示修正として実施した。v27の添付静止画だけから原因を断定したものではない。

## 確認した原因と修正

- 通常の上昇角上限を少し超えただけで、上昇10°付近の案内が水平0°付近へ切り替わっていた。失速等の重要な復帰と分け、通常の超過では上下を同じ上限へ戻し、左右は既存の±15°以内の案内を保つ。失速・出力0・揚力不足の重要復帰では、従来どおり左右0°を即時指示する。
- 目標取得や回り込み切替では上下案内が即座に反転していた。上下にも左右と同じ毎秒150°の変化上限を適用し、現在の迎角・上昇角・上下10°の制限に収める。
- HUDを避けて実際に描いた方向が次の表示へ引き継がれていなかった。輪とFPMを両方表示できた場合に、その輪の実方向を引き継ぐ。
- HUDの角の外側にある狭い候補へ輪を置くと、通常のカメラ移動だけで反対側へ飛んでいた。FPMから輪へ向かう経路もHUDと重ならない候補を選び、前フレームの方向も候補に残す。FPMは動かさない。
- 同じ上昇角の2方向をベクトルで補間して正規化すると、上昇角がわずかに上限を超え、安全判定が補間を破棄していた。方位角と上昇角を別々に補間する。
- 通常の上下境界で片方の角度だけが許容外になった場合に、左右まで生の案内へ戻していた。通常時は上下・左右をそれぞれ現在の許容範囲へ最小限補正し、前の実表示候補も同じ補正を通す。重要復帰は補間せず即時に生の安全指示を使う。

失速余裕17°、出力0、水平維持不能時の即時復帰は維持する。飛行の力・入力・重力・旋回・取得範囲・速度・カメラの計算は変更していない。重要な安全制限へ急に達した場合には、安全な案内を優先するための即時変更が残る。

変更前のGUIを同じ入力で再現すると、区間3→4の旋回合計は7.360radでπを超えた。残り30.5mでも目標が右38.8°に残り、右15°の指示は描画で5〜7.3°へ縮んでいた。上昇角9°で左右をさらに半減し、10°超で左右0°にする処理も重なっていた。回り込み開始時の高度差は0.84mなので、高度不足より旋回不足が主因だった。
