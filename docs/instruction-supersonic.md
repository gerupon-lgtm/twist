# twist 次の版の指示：超音速の「高速空域」を試作する（マッハ1〜2）

作業中の版（スピード感の改善とABの使いどころ）が終わってから、その次の版として出してください。

## 背景（なぜ作るか）

- 発案者の希望：「超音速戦闘機がモチーフなので、音速（約340m/s）を超えたい。可能ならマッハ2ぐらいまで試したい」。
- 今の飛行は、巡航10m/s・最高30m/s・AB中45m/s、ステージは前後左右350mです。この大きさのまま速度だけ上げることはできません（下の計算）。
- 今の遺跡のコースは、操作感がかなり良くなっています（むずかしいコースを約70秒・墜落0回でクリア）。**今のコースはそのまま残し、超音速は別の空域として作ります**。

### 今の大きさで超音速が成り立たない理由（計算）

- 音速を約340m/s、マッハ2を約680m/sとします。
- **ステージ**：端から端まで700mを、マッハ1なら約2秒、マッハ2なら約1秒で横切ります。
- **旋回**：曲がれる円の半径は「速度² ÷（旋回の強さ × tan(翼の傾き)）」です。旋回の強さ9.8・翼35°では、マッハ1で約17kmになります。実機の戦闘機でも、9G（重力の9倍）で旋回しても、マッハ1での半径は約1.3kmです。
- **すり抜け**：1秒に60回描画するとして、マッハ2では1回の描画の間に約11m進みます。今の「その瞬間に近くにいるか」という判定では、目標や地面をすり抜けます。
- **表示の決まり**：速度の表示は実際の速度にする（数値を盛らない）、という決まりは守ります。そのため、世界を本当に大きくします。

## 方針

- 新しい空域は、**試作**です。まず「広い海と雲の上で、マッハ1を超えるまで加速し、km単位の門をいくつかくぐる」ことができれば十分です。景色の作り込みは後回しにします。
- 今のステージ・3コース・飛行の計算・取れる判定は、**変えません**。新しい空域の値は、新しい空域の中だけで使います。

## やること

### 1. 高速空域の追加

- コース選択に「高速空域（試作）」を追加します（URLの例：`course=supersonic`）。選んだときだけ、下の設定で動きます。
- **広さ**：数十km四方（目安：40km×40km）。端の扱いは今のステージと同じ考え方（見えて分かる端、警告、戻る方向の案内）。
- **景色**：
  - 地面の代わりに**海**。大きさの違う波の模様を重ね、低空では速く流れて見え、高空では遠くまで続いて見えるようにします。
  - 高さの違う**雲の層**（低空の雲、中層の雲）。通り抜けると速さを感じられるようにします。当たり判定は付けません。
  - 遠くの**島や山の稜線**のシルエット（方向の手がかり）。
  - 描画を軽く保つため、軽い多角形と繰り返しの模様で作ります。
- **巨大な世界の描画の精度**：自機から遠い座標を扱うと、3D描画の数字の精度が足りず、画面が震えることがあります。自機のまわりを常に原点に置き直す方法（フローティングオリジン）など、震えない仕組みを入れてください。
- **高度**：海面から数km（目安：0〜6000m）を飛べるようにします。海面に触れたら失敗（今の地面の接触と同じ扱い）。

### 2. 高速空域の飛行の計算

今の計算（`flight-physics.js`）とは別の設定として持ち、高速空域でだけ使います。

- **速度**：開始は亜音速（目安：200m/s）。通常の出力で音速の手前まで、ABでマッハ2（約680m/s）まで出せるようにします。
- **マッハ数**：音速は340m/sの一定値で計算します（高度による変化は、今回は入れない。入れる場合は理由を記録）。
- **音速付近の抵抗の増加**：実機と同じように、マッハ0.9〜1.1付近で空気の抵抗が急に増え、ABがないと音速を超えにくい手応えにします（遷音速の抵抗増加）。超えた後は、抵抗がやや下がります。
- **加速の速さ**：実機ではマッハ2まで数分かかりますが、ゲームとして縮めて構いません（目安：ABで開始から1分前後でマッハ2）。**表示する速度は、計算どおりの実際の速度**にします。
- **旋回**：「最大G（重力の何倍まで引けるか）」で制限する形にします。初期値9G（調整パネルで変更可能）。翼の傾きと機首の上げ方から旋回し、Gの上限を超えないようにします。マッハ1・9Gで、半径約1.3kmが目安です。
- **機首の上下**：今の角度方式のまま使います。高速では高度が速く変わるので、上下の効きが強すぎないか確認し、必要なら高速空域用の値を分けてください。
- **失速**：高速では起きにくいはずです。低速まで落ちた場合の扱いは、今の計算の考え方に合わせます。

### 3. 門（ゲート）とすり抜け対策

- 高速空域の目標は、くぐる**大きな輪（ゲート）**にします。半径の目安は60〜100m、間隔は3〜8km、数は5〜6個です。
  - 今の遺跡のコースの「取れる判定（半径3.2m・4m）を大きくしない」という決まりは、今のコースについてのものです。高速空域は大きさの基準が違うので、輪の大きさは新しく決めます。
- **すり抜け対策**：判定は、前の位置から今の位置までの**線分**で行います。線分が輪の面を、輪の内側で横切ったら通過とします。海面との接触も、同じく線分で判定します。
- 配置は、今のコースの検証（`course.js` の考え方）を高速空域向けに広げ、最大Gで曲がりきれることと、AB向きの長い直線があることを確かめます。
- 案内（フライトディレクター、方位の印、画面端の目印、次の目標の知らせ、案内音）、目標高度の目印、レーダーは、km単位でも正しく動くようにします。レーダーの範囲は、高速空域ではkm単位の初期値にします。

### 4. HUDと演出

- **HUD**（英語表記のまま）：
  - マッハ数（例：`M 1.02`）を、速度の近くに大きく表示します。
  - 速度の単位は、今の設定（km/h・m/s・kt）に従います。
  - 高度の単位は、高速空域では大きな数になるので、読みやすい表示にします（例：1000m以上は `ALT 2.4k`）。
  - 今の旋回のG（例：`G 6.2`）を表示します。
- **音速を超える演出**：
  - **ベイパーコーン**：マッハ0.95〜1.05あたりで、機体のまわりに白い円錐状の雲を出します（外から見る視点。操縦席視点では画面の縁に白いもや）。
  - **音速を超えた瞬間**：衝撃音と強い振動を1回（超えるときと、下回るときに各1回）。HUDに短く `SUPERSONIC` などの合図を出します。
  - **風切り音・エンジン音**：速度全域で変化させます。音速を超えた後の音の変わり方は、ゲームとして気持ちよく感じる形を選んで構いません（選び方を記録）。
  - 流線・視野の広がり・揺れは、高速空域の速度に合わせて調整します（今のコースの見え方は変えない）。
- **ABのゲージ**：試作なので、高速空域では「ABの燃料を無制限にする」設定を用意し、初期値を無制限にします。ゲージ制で遊ぶ設定にも切り替えられるようにします。

### 5. 設定と記録

- 調整パネル（高速空域のときだけ表示）：最大G、ABの燃料（無制限／ゲージ）、高速空域用の機首の効き（分けた場合）。
- 記録とコピー：最高マッハ数、マッハ1・マッハ2に達するまでの時間、門ごとの区間時間と通過・失敗、一番近づいた距離、最大G、海面からの最低高度。
- 早見表（`docs/settings-guide.md`）と画面の説明に、新しい設定と略語（M、G など）を追加します。

### 6. 版番号・記録

- 版番号を上げ、README と `docs/verification-v01xx.md` を更新します。高速空域の飛行の計算の数値（抵抗の曲線、推力、最大G）と、門の配置と検証結果を記録します。
- 描画と音の処理の重さを測り、今のコースと比べて記録します。

## 変えないもの

- 今のコースで使う飛行の計算（旋回の強さ9.8、重力3、巡航10・最高30・AB45m/s）と、取れる判定の大きさ。
- 操縦の入力の方式、HUDの英語表記、BGMの仕組み。

## テスト

- 単体テスト：
  - 高速空域の飛行の計算：マッハ数、音速付近の抵抗の増加、ABでマッハ2に届くこと、最大Gを超えないこと。
  - 線分による通過判定：高速でも輪をすり抜けないこと、輪の外を通ったら失敗すること、海面の接触。
  - 原点の置き直しで、位置や判定がずれないこと。
  - 今のコースの飛行の計算が、従来と同じ結果になること。
- ブラウザーテスト：
  - 高速空域を選んで開始でき、疑似操作でマッハ1を超え、門を順にくぐれること。
  - 音速を超えたときに、ベイパーコーン・衝撃音・合図が出ること。
  - 遠くへ飛んでも画面が震えないこと。
  - 今の3コースは、従来どおり動くこと。
  - 390×844・360×640・844×390で、HUD（マッハ数・G）が他の表示と重ならないこと。
- 既存のテストはすべて通ること。
- 実機でのスピード感、操作のしやすさ、酔いやすさ、描画と音の重さは、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 空域の広さ、景色の種類、高度の範囲。
- 速度・推力・抵抗の曲線・加速の速さ・最大G・ABの燃料の扱い。
- 門の大きさ・間隔・数。
- 演出の見た目・音・振動。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 速度やマッハ数の表示を、計算上の実際の速度と違う値にすること。
- 今のステージ・3コース・その飛行の計算と取れる判定を変えること。
- 端末の外へ情報を送る処理の追加（設定と記録は端末内だけで扱う）。
- 開始ボタンを押す前に音や振動を出すこと。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。発案者が不在の場合は、安全側で仮決めして `docs/open-questions.md` に記録し、先へ進んでください。
