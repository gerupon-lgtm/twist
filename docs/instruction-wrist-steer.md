# twist 次の版の指示：3つ目の旋回方式「手首」（ひねりと回しを計算で組み合わせる）

作業中の版があれば、その次の版として出してください。

## 背景（なぜ作るか）

- 発案者の希望：「ひねりと回転を組み合わせて、直感的に動かせないか。加算ではなく計算で。設定で3パターンを切り替えて試したい」。
- 今の旋回の方式は2つです（`relativeAngles` の値を使う）。
  - `steer=tilt`（ひねる）：左右の端の上げ下げ（`steer`）を使う。
  - `steer=twist`（回す）：画面の面内の回転（`twist`）を使う。

### 2つの方式の関係（考え方）

- プレイヤーが旋回しようとするとき、実際にしているのは、**手首（前腕）をくるっと回す動き**です。
- ゲームは、その動きをスマホ本体の向きを基準に、「ひねり」と「回し」の2つに分けて測っています。どちらにどれだけ出るかは、**スマホを持つ角度**で変わります。
  - 画面を上に向けて寝かせて持つ → ほぼ「ひねり」だけが出る。
  - 画面を立てて持つ → ほぼ「回し」だけが出る。
  - その中間（約45°。多くの人の自然な持ち方）→ 両方が同じくらい出る（およそ cos45° と sin45°）。
- そのため、**単純に足すと**、45°の持ち方では同じ手首の動きが約1.4倍に効き、持ち方によって敏感さが変わります。持ち方によっては、2つの値が逆向きに出て打ち消し合うこともあります（推測）。

### 新しい方式の考え方

- 「ひねり」と「回し」を足すのではなく、**手首の軸（前腕の向き）まわりの回転**を、1つの角度として直接測ります。
- 手首の軸は、「持ち方を合わせ直す」ときに、その持ち方から決めます。どんな角度で持っていても、手首を回した角度がそのまま旋回の入力になります。

## やること

### 1. 旋回の方式に「手首」を追加する

- `steer=wrist` を追加し、旋回の方式を3つから選べるようにします。
  - `tilt`（ひねる）・`twist`（回す）・`wrist`（手首：新規）
- 設定画面の「旋回の方式」（①基本の段）で、3つから選べるようにします。URLでも切り替えられるようにします。
- 初期値は今の `tilt` のままにします（比べたうえで、発案者が決める）。

### 2. 手首の角度の計算

**手首の軸を決める（持ち方を合わせ直すとき）**
- スマホの「背面の向き」（画面と反対側を指す向き）と「上端の向き」を、それぞれ水平面に投影します。
- 2つの投影を、それぞれ長さ1にしてから足し、長さ1にしたものを**手首の軸**（プレイヤーから見て前方を指す、水平な向き）とします。
  - 画面を立てて持つと、背面の向きがほぼ水平になり、軸は背面の向きに近くなります（回しと同じになる）。
  - 画面を寝かせて持つと、上端の向きがほぼ水平になり、軸は上端の向きに近くなります（ひねりと同じになる）。
  - 背面の向きと上端の向きは互いに直角なので、両方が同時に真上・真下を向くことはありません。ただし、2つの投影が逆向きに近く打ち消し合う持ち方（スマホを前に倒しすぎた持ち方など）では、大きい方の投影を使うなど、安全な扱いにしてください。
- 軸は、持ち方を合わせ直すまで固定します。

**手首の角度を求める（毎回）**
- 持ち方を合わせ直したときの向きから、今の向きまでの回転を求めます。
- その回転を、手首の軸**まわりの回転**と、**それ以外**に分けます（回転の「スイング・ツイスト分解」）。手首の軸まわりの回転角を、手首の角度とします。右へ回すと右旋回になるよう、符号をそろえます。
- この方法なら、体ごと左右を向く（鉛直の軸まわりの回転）は、手首の角度にほとんど入りません。

**機首の上下との関係**
- 機首の上下（上端を起こす動き）は、今の計算のまま使います。
- ただし、機首の操作で手首の角度が動いてしまう（混ざる）ことがないか、テストで確認してください。混ざりが大きい場合は、機首の角度も「手首の軸と直角な水平の軸」まわりの回転として測るなど、手首の方式のときだけの計算に変えて構いません（理由を記録）。

### 3. 手首の方式の設定

- 手首の方式専用の、中立範囲と「旋回が最大になる角度」を用意します。
  - 中立範囲：初期値 3°（範囲 0〜8°）
  - 旋回が最大になる手首の角度：初期値 25°（範囲 5〜40°）。今の発案者の「ひねる」の値（25°）に合わせます。
  - 効き方のカーブ（`steerCurve`）は、3つの方式で共通に使います。
- まとめ設定「操作の感度」（おだやか／ふつう／機敏）にも、手首の方式の「最大になる角度」を含めます（おだやか30°・ふつう25°・機敏18°）。
- 選んでいない方式の設定は、今までどおり `inactiveSettings` に入れます。
- 早見表（`docs/settings-guide.md`）と画面の説明に、3つの方式の違いと選び方を追加します（例：「持ち方を気にせず、手首を回すように操作したい人は『手首』」）。

### 4. 表示との関係

- `display=fixed`（自機を固定）の、画面の面内の回転を打ち消す処理は、今までどおり `twist` を使います。手首の方式でも、景色は現実の水平を保ちます。
- 手首の方式のときも、ハンドルを回すような見え方になるはずです。違和感がないか、確認項目として記録してください。

### 5. 記録

- 記録とコピーに、旋回の方式（`wrist` を含む）、手首の軸を決めたときのスマホの持ち方の角度（画面を立てているほど90°に近い、など分かる値）、手首の角度の揺れ幅を追加します。
- 3つの方式を比べられるよう、今の `sensorJitter` の旋回の揺れ幅は、選んでいる方式の値で記録します。

### 6. 版番号・記録

- 版番号を上げ、README、`docs/settings-guide.md`、`docs/verification-v01xx.md` を更新します。手首の角度の計算方法を、図や式で記録します。

## 変えないもの

- `tilt`・`twist` の計算と、その設定値。
- 飛行の計算、コース、取れる判定、案内、HUD、音、振動。
- 発案者の端末に保存されている設定値（旋回の方式も含め、勝手に `wrist` へ変えない）。

## テスト

- 単体テスト（作った向きのデータで確認）：
  - 持ち方の角度を 0°（画面を上に寝かせる）・30°・45°・60°・90°（画面を立てる）に変えて、それぞれ手首の軸まわりに右へ15°回したとき、**手首の角度がどれも約15°になる**こと。同じ条件で、`tilt` と `twist` の値は持ち方によって変わること（比較のため）。
  - 機首の上下の操作だけをしたとき、手首の角度がほとんど動かないこと（許容する混ざりの大きさを決めて確認）。
  - 体ごと左右を向いた（鉛直の軸まわりの回転）とき、手首の角度がほとんど動かないこと。
  - 中立範囲・最大の角度・カーブ・符号。
  - 2つの投影が打ち消し合う持ち方でも、値が壊れない（有限で安全な値になる）こと。
  - 縦持ち・横持ち（左右どちら向きでも）で、同じように動くこと。
- ブラウザーテスト：
  - 設定で3つの方式を切り替えられ、保存されること。URLでも切り替えられること。
  - 疑似センサーで、手首の方式で右へ回すと右へ曲がること。
  - `display=fixed` でも、景色の補正が今までどおりであること。
- 既存のテストはすべて通ること。
- 実機での直感的さ、3つの方式の比較は、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 手首の方式の初期値・範囲、まとめ設定に含める値、初期の旋回の方式。
- 手首の軸の決め方の細部（投影の重み付けなど）、機首の角度の測り方を手首の方式用に変えるかどうか。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- `tilt`・`twist` の計算を変えること（比較のために残す）。
- 保存済みの設定を、本人の操作なしに書き換えること。
- 端末の外へ情報を送る処理の追加。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。発案者が不在の場合は、安全側で仮決めして `docs/open-questions.md` に記録し、先へ進んでください。
