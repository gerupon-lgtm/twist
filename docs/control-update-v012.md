# twist 操作検証 v0.1.2

現在の2モードは [v0.1.3 飛行機モード](flight-mode-v013.md) を参照。以下の自機基準操作は探索モードの基礎として継続する。

2026-11-07。利用者が確認した『画面の中で自機の先端がある側へ倒すと加速、逆へ倒すと制動』を操作基準として明示する。

## 確認した前提

- ユーザーは、スマホを回した後も自機の見えている先端側を下げて加速、逆側を下げて減速する操作を指定した。斜めの向きでも同じ。
- 自機基準の操作と、他にも直感的に使える動きへ実装するよう依頼。前回までの送信・GitHub Pages公開の承認は継続。
- 旧版の分解も、平面の0/±90/180/斜め回転後の単独傾きでは意図に合う。『スマホ本体の上辺に常に固定されていた』という説明は不正確。
- 旧版は画面の自動縦横変更で一時停止・基準消去・再設定を行い、物理的な自機の向きが変わり得た。また複合傾きの分解と、見えている先端への傾きには差があった。

## 実装する判断

- 自機を描く回転から、画面上の先端と、それに直交する左右方向を求める。先端方向の面を下げて加速、逆へ制動。右側を下げて右旋回、左側を下げて左旋回。
- 自機の物理的な向きの基準は初回開始時に保持する。持ち直しや停止からの再開は操作の中立だけを合わせ直し、機体の上向きを別の方向へ取り直さない。最初からやり直す場合は新しい出発基準にする。
- 操作用の姿勢は基準合わせ時の画面角で計算し、描画用は現在の画面角で計算する。画面の自動縦横変更だけでひねり入力が生じないよう分ける。
- 縦横の表示変更では、有効な直近データを使って再描画し基準と速度を保つ。データ受信時刻は更新しない。画面非表示・フォーカス離脱・センサー消失では従来どおり速度0と手動再開。
- ひねりで上下へ曲がる選択は継続。半回転をまたぐときの急反転を避け、0/180/360度付近では旋回が中立へ戻る連続的な反応とする。通常の小さいひねりの感度は維持。
- 前後の中立で速度維持、制動で停止、後退なし、一時停止で速度0を継続。
- 自機が真横に見えるなど先端が定義できない角度は、有限な中立入力へ戻し速度0で停止して持ち直しを案内する。この領域も検証に含める。
- 練習用のつまみは『端末の上辺』『端末の右辺』『端末の回し角』に変更し、実センサーと同じ姿勢計算を通す。回した後に、先端側の辺を下げて操作を確かめられるようにする。PCキーは自機基準の操作を継続。
- v0.1.2表示、ホーム・アイコンの版、ビルドのハッシュ付きJS/CSSを更新する。

## 共有する計算の取り決め

`projectedTiltAngles(craftCompensation,neutralCompensation=craftCompensation)` は `{pitch,steer,valid}`。先端は `projectXY(craftCompensation * Y)`、右は先端に直交する画面内の方向。基準面の法線は `neutralCompensation * Z`。各方向と法線から面の傾き角を求め、pitch<0で加速・steer>0で右旋回。先端の長さが小さい、又は法線が表側を十分向いていない場合valid=false。
`composeDevicePose({pitch,steer,twist})` は練習用の回転を返す。clockwise twistの後に端末自身のX/Y軸で傾ける順序（`Rz(-twist) * tiltXY`）。pitch<0は端末上辺を下げる、steer>0は端末右辺を下げる。
`controlRates()` は通常の前後・左右入力の意味と上限を維持。上下旋回のひねりのみ `asin(sin(twist))` の度数へ折り返してから既存の反応範囲へ変換し、半回転の境で急反転しない。

## 検証

0/±45/±90/180/360度、斜め持ち、複合傾き、自機の見える先端・逆側・左右、画面角のみの変更、実際の姿勢と画面角が同時に変わる場合を含める。計算・画面・疑似センサーを区別し、スマホ実機の結果は未確認として残す。空中目標の取得と出口への到達も維持する。
