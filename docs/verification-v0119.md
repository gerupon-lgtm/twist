# v0.1.19 PWA・向き固定・iPhoneの案内

v0.1.17の振動/効果音、v0.1.18のMIDI BGMをそれぞれ公開確認してから実装。[指示資料](instruction-pwa.md)に加え、ユーザーの「iPhone検知時は向き固定のトースト」を優先する。停止時0、手動再開時50%・6m/sという過去の直接回答を継続する。

## 実装と条件

- ホーム画面の名前はtwist。manifestはfullscreen/any、開始URLは飛行機・見失い対策・angle・tiltに版番号を追加。scope/id/アイコンは相対パス。192/512/マスク用512/Apple用180のPNGは、既存faviconと同じ六角形と交差線から自前生成。ビルド時に版番号とmanifest/version.jsonも同期する。MIDIはビルドで上書きしない。
- サービスワーカーを採用。インストール/起動条件のブラウザー差に備え、通信を受ける処理を置くが、CacheStorageは使わず毎回no-storeで通信。オフライン用ファイルや代替画面は保存しない。旧処理はskipWaiting/clients.claimで置き換える。登録URL、manifest、アイコン、HTMLの版付きリンクとViteの内容ハッシュで更新する。既存画面を開いたまま復帰した場合もversion.jsonを確認し、新しい版があれば停止して更新ボタンを出す。勝手に飛行途中を再読込しない。
- Androidは最後の開始/再開ボタン（センサー許可用の最初のボタンとは別）と画面操作開始から全画面を試し、その前に記録したscreen.orientation.typeそのものへ固定する。portrait/landscapeのprimary/secondaryを保つ。失敗や非対応でも遊べる。合わせ直しで再固定。一時停止に解除ボタン。ホーム画面アプリのfullscreen表示はOS側のため、exitFullscreenだけではバーが戻らない場合の説明とブラウザーリンクも用意。
- iPhoneはアプリから固定しない。開始画面の見出し部分に10秒のトーストを出し、閉じることも可能。縦はコントロールセンターの縦向きロック、横は縦向きロックで横固定できないことを案内。開始後に画面の向きが変わったら停止し、元の向きへ戻すまでは開始/入力切替を無効にする。戻っても自動再開せず、新しい持ち方のセンサー値で合わせ直す。手動停止中に持ち替える場合と、新ステージの明示リセットでは別の向きから開始可能。
- iPhoneブラウザーには共有メニューからの追加方法を表示。Androidの追加ボタンはbeforeinstallpromptが来たときだけ表示。すでにアプリ起動なら追加案内を隠す。起動時の方式を固定してlaunch=browser|installedをコピー/結果へ追加し、後から全画面になってもinstalledへ読み替えない。fullscreenはコピー/結果時点の実際の状態。
- 正式URLはhttps://twist.sikumilab.com/。旧GitHubの設定はドメインが異なるため移らず初期値になる。設定を端末外へ送る処理、移行処理は加えない。

## PCでの確認

- 単体148件（122件/5ファイルと26件/3ファイル）、終了コード0。端末・起動・案内・向きの判定、停止後に戻して再度外れた場合の保持を含む。
- PWAの端末再現11件、Edge・1worker・22.6秒、終了コード0。3サイズのiPhoneトーストの実描画、閉じる/10秒、他端末非表示、3方向の停止/復帰、探索、手動持替え、Androidの向き記録順・合わせ直し・解除、両API拒否でも継続、追加案内、コピーを確認。最初のAndroid試験失敗は、HTML要素ができる前に試験用APIを割り当てたfixtureの問題。Element.prototypeの割当へ修正して11件成功。
- ビルド配信の5件、11.5秒、終了コード0。ルートと/twist/双方でHTML/3D/manifest/PNGの型・寸法・相対パス・開始条件・SW scopeを確認。旧版fixtureの処理から現行へ交代し再読込でv0.1.19、CacheStorageなし、オフライン取得失敗と復帰後の取得成功を確認。開いたままの画面に新版を知らせた際の停止/更新ボタン/選択URL保持も確認。
- 既存の全105種類のブラウザー試験・レビュー・公開確認は実行後に追記する。

## Pixel 9a 実機手順（未確認）

1. Chromeで[公開URL](https://twist.sikumilab.com/?mode=flight&v=0.1.19)を開き、トップのv0.1.19を確認。追加ボタンが出れば押し、出なければChromeのメニューから追加/インストールする。追加できたかを記録する。
2. ホームアイコンから起動し、追加案内が出ないこと、バーが隠れる範囲と記録のlaunch=installed/fullscreenを確認。縦/横の左右それぞれで、許可後「この持ち方で飛ぶ」を押し、傾けても画面の向きが切り替わらないかを確認。飛行入力と表示を区別する。
3. 一時停止→解除。バーの戻り方と回転が戻るかを記録。ホームアプリでバーが戻らなければ説明からブラウザーで開く。持ち替えて「持ち方を合わせ直す」→開始で新しい向きに固定されるか確認。
4. 全画面/向き固定ができないブラウザーでもゲームを始められるか確認。音・振動・BGMを同時に使って1分以上遊び、計測とコピーを残す。
5. 次の版が公開されたら、ホームアイコンの新規起動と開いたままの画面への復帰の両方で版番号/更新案内を確認する。PC成功を実機成功へ置き換えない。

## iPhone XR 実機手順（未確認）

1. Safariで公開URLを開きv0.1.19とトーストを確認。縦でコントロールセンターの「画面縦向きのロック」をオンにして遊ぶ。閉じる/10秒で案内が消えること、ボタンが隠れないことを確認する。
2. 縦ロックをオフにして縦から開始し横に変える。速度/出力0で止まり、開始時の向きへ戻す案内になるかを確認。縦へ戻すと合わせ直しのボタンが使え、押すまで止まることを確認する。横から縦、横の左右の入替えも試す。
3. 横で開く場合はトーストが横向きロックを勧めず、縦ロックが縦専用だと説明するか確認。手動で一時停止して持ち替え、新しい向きから手動再開も試す。
4. Safariの共有→ホーム画面に追加（「Webアプリとして開く」があればオン）→追加アイコンで起動。追加方法の案内が消え、launch=installedとなるか、ステータスバーと安全領域、音を確認する。
5. 次の版が公開されたらホームアイコンからの新規起動/既存画面復帰で新版になるか確認。オフライン対応はなく、通信できない場合の起動は保証しない。

実装の参考：[画面の向きの仕様](https://www.w3.org/TR/screen-orientation/)、[Chromeのインストール条件の変更](https://developer.chrome.com/blog/update-install-criteria)、[Appleの画面回転案内](https://support.apple.com/ja-jp/118226)、[Appleのホーム追加手順](https://support.apple.com/ja-jp/guide/iphone/iphea86e5236/ios)。端末/OSによる違いを残し、ホーム追加/ロック/実際の音を確認済みとは記載しない。
