# twist 次の版の指示：スタート画面からの導線の整理（友人向け）

「設定画面の整理・まとめ設定・初期値の見直し・BGMの選び方」の指示と**同じ版で行って構いません**（発案者は「今回の修正で導線も整理したい」としています）。ブリーフィング（上から見た地図）がまだ実装されていない場合は、この流れの中に組み込んでください。

## 背景（なぜ整理するか）

- 発案者は、友人に遊んでもらうために、スタート画面からプレイ開始までの流れを整理したいと考えています。
- 今のスタート画面（`index.html` の `intro-card`）は、1枚のカードに、遊び方（探索／飛行機。初期値は探索）、コース、見え方、旋回・機首・機体表示・視点の方式、開始ボタン、画面で操縦、ホーム画面に追加、全画面の解除、更新のお知らせ、結果の記録が全部並んでいます。検証のために選択肢を足してきた結果、初めての人には何を選べばよいか分からない画面になっています。
- **全画面の注意文の問題**（発案者の実機での報告）：全画面に切り替えた直後、画面の下に「全画面表示を終了するには、上部からドラッグして[戻る]ボタンをタップします」という注意文がしばらく表示され、**スロットルに触れなくなります**。この表示はブラウザー側が出すもので、アプリからは消せないと見ています（機種・ブラウザーによる。推測）。そこで、**全画面に切り替えるタイミングを早め**、注意文が消えるまでの時間を、プレイ開始前の画面で過ごしてもらう形にします。

## 発案者が決めたこと

- 探索モードは隠す（検証用へ移す）。
- 視点の切り替えは、スタート画面でも、プレイ中でも操作できるようにする。
- 画面で操縦（傾きを使わない練習）は隠す。設定画面で選べるようにする。
- 初めての人向けの説明は、初回だけ出す。
- 全画面には早い段階で切り替える。

## やること

### 1. 画面の流れ

1. **タイトル**
   - ロゴと、大きな「はじめる」ボタン。小さく「設定」「遊び方」。
   - 「はじめる」を押した瞬間に、**全画面に切り替えます**（全画面への切り替えは、ボタンを押すなどの操作の中でしか行えないため、最初のボタンで行います）。
   - ホーム画面に追加の案内、更新のお知らせは、タイトルの下に控えめに置きます（今の条件どおり、必要なときだけ）。
2. **初めての人向けの説明（初回だけ）**
   - 傾け方を3枚程度の絵と短い文で見せます（例：上端を起こすと上昇、左右の端を上げ下げすると旋回、スロットルで加速・右端の先でAB）。
   - 「次へ」「スキップ」で進めます。2回目からは出しません。タイトルの「遊び方」から、いつでも見返せます。
3. **コース選択**
   - カード形式で「やさしい／ふつう／むずかしい（／高速空域があれば）」を並べ、自己ベストを添えます。小さな地図の絵があると分かりやすいです。
   - **視点の切り替え**（外から／追尾3D／操縦席）を、この画面にも置きます。前回選んだものを覚えておきます。
4. **ブリーフィングの地図**（スキップ可。表示の設定に従う）
5. **構える**
   - 「楽な持ち方で構えて、ボタンを押してください」と表示し、押した時点の持ち方を中立として記録します。
   - センサーの許可が必要な端末では、ここで許可を求めます。
   - **向きの固定**（Android）は、ここで、構えた画面の向きで行います（全画面はタイトルで済んでいる）。
6. **カウントダウン**：3・2・1の後に飛行開始。構えた姿勢のまま、落ち着いて始められるようにします。タイムはカウントダウンの後から数えます。
7. **結果**：タイムと自己ベスト、「もう一度」「コース選択へ」「記録をコピー」（コピーは小さく）。

- タイトルからカウントダウンまでの間に、全画面の注意文が消える時間（目安：数秒）が取れるようにします。もし注意文がまだ出ている間にカウントダウンが終わりそうな場合の工夫（カウントダウン前に少し待つなど）は、Codexが判断して記録してください。
- 全画面がプレイ中に解除された場合（注意文の操作などで）は、今の一時停止と同じ安全側の扱いで止め、再開の前に全画面への切り替えを案内します。

### 2. プレイ中の視点の切り替え

- 飛行中に、視点を切り替えられる小さなボタン（例：`VIEW`）をHUDに置きます。押すたびに「外から → 追尾3D → 操縦席」の順に切り替えます。
- スロットルや他のボタンから離れた位置に置き、誤って押さないようにします（例：画面の上側）。
- 切り替えても、位置・向き・速度・タイムはそのまま続けます。

### 3. 一時停止の画面

- 「再開」「持ち方を合わせ直す」「MAP」「視点」「設定」「コース選択へ」を置きます。
- 「コース選択へ」は、今の飛行を終える確認を出してから移ります。

### 4. 隠すもの・移すもの

- **探索モード**：検証用（`?dev=1` などで見える段）へ移します。通常は飛行機モードで始まります。
- **画面で操縦**：設定画面の「操作の方法：スマホの傾き／画面で操縦」として選べるようにします（設定の②詳しい設定に置く）。センサーが使えない端末では、その旨を案内して、この設定を勧めます。
- **見え方（見失い対策／従来）、機首の方式、機体表示（傾く／固定）、旋回の方式**：スタート画面から外し、設定画面の該当する段へ移します（旋回の方式は①基本、機体表示は②、見え方「従来」と機首「回り続ける」は④検証用）。
- **全画面と向き固定の解除**：一時停止の画面か設定画面へ移します。

### 5. 記録

- 記録とコピーに、全画面にした時点（タイトル／それ以外）と、飛行開始までの時間、カウントダウンの有無を追加します。
- 説明を表示したかどうか（初回かどうか）も記録します。

### 6. 版番号・記録

- 版番号を上げ、README（遊び方の流れ、検証用の開き方）と `docs/verification-v01xx.md` を更新します。

## 変えないもの

- 飛行の計算、コース、取れる判定、案内・HUD・音・振動の内容。
- 発案者の端末に保存されている設定値。
- 検証用の機能そのもの（隠すだけで、消さない）。

## テスト

- 単体テスト：
  - 初回の説明の表示判定と保存。
  - 視点の切り替えの順番と、切り替えても飛行の状態が変わらないこと。
  - タイムがカウントダウンの後から数えられること。
- ブラウザーテスト：
  - タイトル → 説明（初回だけ） → コース選択 → 地図 → 構える → カウントダウン → 飛行 → 結果、の流れが通ること。2回目は説明が出ないこと。
  - 「はじめる」で全画面への切り替えを要求すること（できない環境でもエラーにならないこと）。
  - 飛行中の `VIEW` ボタンで視点が切り替わること。
  - 一時停止の各ボタン、「コース選択へ」の確認。
  - 探索モード・画面で操縦・見え方「従来」が、通常は表示されず、設定や検証用の段から選べること。
  - 開始ボタンの前に音や振動が出ないこと（試聴を除く）。
  - 390×844・360×640・844×390で、各画面が読みやすく、ボタンが押しやすいこと。
- 既存のテストはすべて通ること。
- 全画面の注意文が消えるまでの時間と、スロットルに触れられるようになるタイミングは、Pixel 9aでの確認を「未確認」として記録に残してください。

## 判断の範囲

**発案者（田中）の指示で変えてよいもの**
- 各画面の見た目、文言、ボタンの配置、説明の枚数と内容、カウントダウンの長さ、`VIEW` ボタンの位置。
- 全画面に切り替えるタイミング（タイトルより後にする場合も含む）。
- 実装方法（より良い方法があれば、理由を記録して採用してください）。

**変えないもの（指示があっても確認してから）**
- 検証用の機能を削除すること（隠すだけにする）。
- 保存済みの設定を、本人の操作なしに書き換えること。
- 試聴以外で、開始ボタンを押す前に音や振動を出すこと。
- 端末の外へ情報を送る処理の追加。

分からない点や、この指示どおりでは難しい点があれば、勝手に範囲を狭めずに、理由を書いて質問してください。発案者が不在の場合は、安全側で仮決めして `docs/open-questions.md` に記録し、先へ進んでください。
