# v0.1.29 モード別HUDと下部表示の整理

下部に調整用の入力値と実際の操作が混在し、景色の見える範囲が狭くなっていた。利用者の追加依頼と「速度・高度もHUD側へまとめる」という選択に基づき、表示構造を変更する。音楽・地面の指示資料にあったHUD構造の維持より、この後の明示依頼を優先する。HUDの英語／日本語設定と実速度の単位換算は維持する。

## 表示の分担

- 外から見る従来視点／追尾3D：左に速度、右に現在高度・目標高度と差・昇降速度・必要な警告。中央には実進路と案内の輪を残す。
- 操縦席：既存の速度・高度・昇降・方位などの計器を使う。外視点用の小さいHUDは重ねない。
- 探索：速度・高さ・目的地の高度情報を表示。飛行機の姿勢計器、スロットルとAB、飛行の昇降値は表示しない。
- 下部：飛行機はスロットル・AB・一時停止・持ち方合わせ／入力切替・ヘルプ、探索は必要な操作ボタンを残す。通常プレイでは入力状態・傾きゲージ・操作説明・機首／翼の詳細数値を隠す。
- 画面のスライダーで操縦する場合のパネルは実際の入力なので残す。探索にも折りたたみ用の見出しを出し、初期の開閉は従来のまま。つまみ44px・操作ボタン40pxの触る面を維持する。
- 地面接近・失速の警告は削除せず高度側へ。出力0で失速しているだけの日本語表示は「失速」とし、補助が働いている説明と分ける。

既存の速度・高度・目標高度の要素を移動して、単位・翻訳・更新処理・コピー・入力の検証を維持した。見た目の整理で、力・取得判定・入力を変更しない。

## 試作中に見つけた問題

最初の1枚カードは、数値・寸法・操作の12件に通ったが、360×640の追尾視点で実進路の印を覆った。実画像で`FPM OBSCURED`を確認し、その状態を受入済みとしなかった。左右の小カードへ分け、中央を空ける構造へ変更した。全面の透明な親領域を障害物として扱わず、実際の2枚の矩形だけを、案内・レーダー・端の矢印・目標ラベル・境界警告の回避対象にする。

数字の可読性だけでは、プレイに必要な案内が残ることを保証できない。このため3視点×3寸法の9条件で、開始直後の案内準備完了、輪と実進路の両方の実表示を必須に追加した。実進路そのものを動かしたり、隠す判定を緩めて通していない。

## 確認済みと残り

`tests/mode-hud.spec.js`の強化14件は全成功。

- 飛行3視点×390×844／360×640／844×390の9条件。初期FD/FPM、表示の分担、速度・高度の実数値、目標高度、英語、画面内・他の表示との非交差、操作面と停止／再開。
- 探索の同3寸法。飛行専用の操作なし、速度・高さ・目的地の可読性、下部の小型化。
- 日本語とktの設定保存・再開後の反映。
- 描画fixtureとして、実AoA25度・補助0の「失速」を表示し、実際の機体位置を変えないこと。

12画面の画像を確認した。左右へ分けた追尾360×640で、中央に輪と実進路が見えることも確認。探索の開始toastはHUDを横切らないよう下部操作の直上へ移した。

横画面の入力パネルを明示的に開くと左SPDに15pxの重なりがあったため、横画面だけSPDをレーダーの右隣へ固定した。変更後の強化14件と、入力を明示openしたoverlay／chase2件は全成功。地面警告・境界・端矢印・レーダー等を合わせたgeometry30件も最終の凍結ソースで成功した。親の透明全面領域を障害物扱いせず、2枚の実カードだけを使う。

独立レビューで、探索の既定openは最初の14件の対象外だったと分かった。14件は傾き操作時相当の小さい下部を確認するためパネルを畳んでいたが、探索の画面操作は初期から開く。未修正の360×640を追加で実行し、速度と下部操作の交差を再現した（1件失敗・8.13秒）。操作を隠す方法は使わず、実パネルへ重なる場合に速度をレーダー横へ配置する処理へ修正。最初のログ・画像は.cache/v0129-explore-open-first-*へ保存した。

探索の既定openを3寸法、操縦席で実際に出力0・機首上げから失速へ入る1条件も加え、最終の対象は18件とする。外視点／操縦席の失速表示は同じ実角度の閾値を参照し、力を変えず、補助なしの日本語は「失速」とする。同じ警告を読み上げ用領域へ繰り返し書かない確認も追加した。実際の読み上げソフトでの確認は未実施。

更新した18件はすべて成功（35.2秒）。最終ログは.cache/v0129-mode-hud-final-log.txt。関連単体30件も成功。360と844の入力を開いた実画像も確認した。

横向きの入力欄は従来から幅260px・最大42vh・内部スクロールの仕様である。新試験の「全3入力を同時に画面内」はこの前提に合わなかったため、入力欄を作り直して通す方法は採らなかった。各入力へ内部スクロールし、画面内・有効・キーによる値変更と戻しを全3本で検証する方法へ訂正し、スクロール後もHUDと操作欄が交差しないことを確認した。入力・履歴・操作の範囲を減らしていない。

旧固定座標へ一致させる試験は、利用者のHUD構造変更に合わせて同じ画面条件の可読性・非交差・操作面へ更新する。目標高度の旧親要素の期待と、地面警告が下部に入る期待は、新しい親と高度側のカードに合わせる。非表示にした入力の値・機能の検証は残す。

既存全件と公開先の確認は版全体の検証へ合流する。Pixel 9aでの読みやすさ・操作感・警告の気づきやすさは未確認。
