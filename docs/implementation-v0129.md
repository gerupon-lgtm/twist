# v0.1.29 実装方針

利用者の追加改修とBGM3案を、公開済みv0.1.28（9e59480）に追加する。添付文書は利用者が今回実装を依頼した仕様として扱い、以前の参考音源や他者MMLを配信へ転用しない。

## 範囲

1. assistedの地面全体へ大小の繰り返し模様、コース沿いの通過物とAB入口／出口の印。view=classic／view=legacyの見た目は維持。
2. 風切り音を実速度0〜45m/sで変化、AB点火・轟音・解放、近くを通った時の短い音。警告優先、振動は維持。
3. ABでは通常曲を進めたまま、拍に合う打楽器MIDIを重ねる。最低3秒保持、停止・設定オフは即解除。共有音源の制約上、旋律の追加で既存5音を奪わない方式を採る。
4. 各コースへ200m／300m／300m以上のAB直線。曲がり角の後に整列の余裕を取り、直線後に急な曲がりを置かない。旧巡航時間の帯は、長い直線を加えるコース変更に合わせて見直し、通常の旋回・飛行の計算は変えない。
5. 区間の最接近距離と15m付近の通り過ぎ、コース別タイム・自己ベスト・直線でのAB利用を端末内に記録。
6. 保存済みradarRange=60は一度だけ180mへの更新を案内し、本人が選ぶ。手動設定を黙って書き換えない。
7. 追加設定、記録コピー、早見表、可視版情報とキャッシュ更新値、前後の描画・音負荷の比較、全既存試験と新機能の検証、公開先の確認。
8. Ignition Sky（165 BPM）、Steel Advance（145 BPM）、Overdrive Horizon（175 BPM）の提供MML主題を使い、展開を加えて約90〜110秒の曲へ。既存9 MIDIは保持する。
9. 「輪が急に飛ぶ・位置が大きく変わる」という利用者の回答に対応。通常の上昇角境界で指示が水平へ急変する処理、目標取得時の上下反転、HUD障害物が消えた時の戻りを滑らかにする。失速・低速・出力0等の重要な復帰指示は即時性を保つ。実際の進路の印、物理・入力・取得判定は変更しない。
10. 利用者の追加依頼により設定画面のBGM試聴を追加する。押したときだけ試聴用の音源を作り、本編の音源は停止したままにする。閉じる・停止・再開・非表示で試聴用音源を破棄。本編の曲順・飛行回数・記録を変えず、初期表示では鳴らさない。
11. 利用者の後続依頼によりモード別HUDへ整理する。外視点の速度は左、高度・目標情報は右、操縦席は既存計器、探索は移動・目的地情報とする。通常プレイの下部診断ゲージを隠し、実際の操作面と警告を維持。初案で追尾の進路印を覆う問題を修正し、初期の輪/FPMを3視点×3寸法で必須確認する。資料のHUD構造維持より後の明示依頼を優先する。

## この後の公開順

利用者の追加指示と添付briefing／start-flow資料により、v29公開後はv30の開始前地図と開始導線、その完了後にv31の高速空域（マッハ対応）へ進む。各版を別々に実装・全検証・公開する。開始前地図の閲覧時間はコース時間に含めず、初期「毎回表示」、一時停止時のMAP、端末内設定・記録に対応する。新しい開始導線はタイトル→初回説明→コース選択→地図→構える→カウントダウン→飛行→結果とし、保存済み設定と検証用機能は維持する。高速空域も同じ地図用データを使えるよう設計する。

## 共有するデータ

- course.abStraights：id、from/to（x/y/z）、width（全幅m）、heightTolerance。stage.setGroundPatternStrength(0〜1)、stage.getPassObjects()、状態のgroundPattern／abLaneを追加する。物理計算と取得半径は維持。
- 音設定：passbySound、abMusicは初期オン。地面の濃さgroundPatternStrengthは0〜1、初期0.8。
- 曲の選択：新曲id ignition／advance／overdrive、曲集proposals、全曲allは10曲。従来のcurrent等と保存値を維持し、曲集上限を16へ広げる。
- tracks.jsonのflightTemposで通常曲のBPMを管理。afterburnerはAB Pulse、ch10だけの16拍・120 BPM・8秒ループ、bpm=120／minSeconds=3。既存曲の設定へBPMを足して書き換えず、最上位の対応表を使う。
- AB用の予約書込みには専用タグを付け、AB設定だけの解除では通常曲の予約や演奏中の旋律を消さない。一時停止・全体音オフでは本編も止める。音楽用PSGと効果音用PSGの分離を保つ。

## 検証と未確認

公開済みv28のビルドを.cache/v0129-baselineに保存した。比較は同じ従来コース・視点・通常曲で行い、実速度と実AudioWorkletの状態を測る。実機の速度感・音・爽快感・負荷はPixel 9aでの確認項目として残し、PCの成功で代替しない。技術的に成立しない条件が見つかった場合は、範囲を黙って外さず理由を示す。
