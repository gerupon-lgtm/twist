## 音源と実装判断

- SCC 0.8.12、コミット0036288a134a79b1855915eac47ff09634295e7fのcore全11ファイルを同梱。各SHA-256をsrc/vendor/scc/source.jsonに記録し、元のバイトと一致する単体試験を追加。元ソースは変更しない。NOTICEはpublic/licenses/SCC-NOTICE.txt。Gitの改行変換もvendorとNOTICEには適用しない。
- Viteのworker URL取り込みで専用AudioWorkletを依存ファイルごとビルドし、内容ハッシュを付ける。固定publicパスを複数キャッシュする方法より、エントリーと依存の更新が一体になる。MGS/MGSDRVは取り込まない。
- SCC5音+BGM用PSG1台を予約し、この版は効果音用の別PSGだけを使用。PsgStageの既存PSG_GAINをそのまま使用。SCC/PSG計算は未改変、混合とレジスタ制御だけtwist側。初期全体音量25%。音色の仮値はfeedback/model.jsに集約。
- PSG Aは出力による低音と速度による風ノイズ、Bは迎え角14〜20度のバフェット/20度以降の失速警告/赤い対地警告、Cは光・ゴール・墜落。出来事中はAを下げ、Cを大きくして埋もれにくくする。ノイズの高さは1チップ内で共有されるため墜落→バフェット→風の順に優先する。BGM用PSGへ効果音は書かない。
- 振動はミリ秒のオン/オフで、倍率は一定周期内のオン時間の割合を変える。通常は400msに最大5ms程度、迎え角14度から増加、20〜70度で不規則な長短の割合を増やす。赤い地面警告は85/100/85/430ms、音も同じ周期。Exploreでは飛行専用の地面警告は出さない。
- 振動は出来事が連続振動より優先。光は短く2回、ゴールは3拍、墜落は320ms1回。資料の「出来事を知らせる」と「墜落/ゴール後に止める」を、連続振動とエンジンを即停止→一回の通知だけ→明示的にvibrate(0)で終了、と解釈した。ユーザーが一時停止/画面を離れる場合は通知もすぐ打ち切る。
- AudioContextは開始ボタンのクリックからだけ作成/再開。許可要求の呼び出し順は変えない。準備失敗・非対応でも音なしでゲームは継続。音/効果音/音量、振動/倍率/通常の震えを端末内だけに保存。振動APIがない/iPhoneなら設定を隠し、非対応と表示する。
- 揺れ幅は直近1秒の機首/選択旋回軸の入力角度の最大−最小。角度境界を折り返して計算し、完成した1秒窓の平均/最大を記録。意図的な操作も含み、振動混入を証明する値ではない。振動設定変更で計測を区切る。計測は上部「計測」から開く。
- 音源負荷はSCCと同じく処理中のDate.now経過時間/処理した音声時間の比、1秒窓と最大。描画・操作はメイン処理のCPU時間/フレーム。GPU/端末の全負荷の測定ではない。コピーにfeedback.settings、sensorJitter、audio、frameCpuを含める。
